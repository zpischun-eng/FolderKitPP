# FolderKit++ 매뉴얼용 화면 캡처 관리 문서

이 문서는 사용 매뉴얼 제작에 쓰는 화면 캡처 이미지들을 관리한다.
기능이 추가되거나 화면이 바뀔 때마다 **이 문서와 `tools/manual_capture_*.py`
스크립트를 함께 갱신**하고, 스크립트를 다시 돌려 이미지를 새로 뽑는다 —
캡처 이미지를 수동으로 하나씩 다시 찍지 않아도 되게 하는 게 목적이다.

- 이미지 저장 위치: `docs/manual_captures/`
- 완성된 사용자 매뉴얼(PPTX): `docs/manual/FolderKitPP_사용자매뉴얼_v43.10.pptx`
  — 위 캡처 25장을 바탕으로 20슬라이드로 제작(pptxgenjs, Midnight Executive
  팔레트). 화면이 바뀌어 캡처를 다시 뽑았다면 이 PPTX도 다시 만들어야
  최신 상태가 유지된다 — 생성 스크립트는 이 문서에 보관해 두지 않았으니,
  다시 만들 때는 새 대화에서 이 문서의 이미지 목록 표를 참고해 슬라이드
  구성을 다시 짜면 된다(표지 → 개요 → Part 1: 본체 4모드 → Part 2: Util
  모드 미니앱 → 마무리 순서, 이미지는 실제 픽셀 크기에 비례해 여백 안에
  맞추는 방식을 반드시 쓸 것 — 그러지 않으면 스크린샷이 슬라이드를
  넘치는 문제가 재발한다).
- 캡처 스크립트:
  - `tools/manual_capture_basic.py` — Util 모드(미니앱) 기본 화면
  - `tools/manual_capture_extra.py` — Util 모드 팝업·부가 상태
  - `tools/prepare_manual_demo_data.py` — 본체 4모드용 더미 폴더/파일 준비(먼저 실행)
  - `tools/manual_capture_main_modes.py` — 본체 4모드(동기화·이름 변경·이미지 편집·중복 찾기)
- 마지막 갱신: v43.10 (2026-09-22) — 본체 4모드 캡처 추가

## 사용법 — 이미지 다시 뽑기

Qt가 설치된 환경(개발용 리눅스 컨테이너 기준)에서, 프로젝트 루트 폴더로 이동해
아래 스크립트를 순서대로 실행한다. 전부 `docs/manual_captures/`에 직접
저장하므로 별도 경로 지정은 필요 없다.

```bash
cd FolderKitPP_v43.10
rm -rf ~/.config/SRIHS          # 이전 실행 기록(QSettings)이 남아있으면 화면이 지저분해진다 — 반드시 먼저 지운다
QT_QPA_PLATFORM=offscreen python3 tools/manual_capture_basic.py
QT_QPA_PLATFORM=offscreen python3 tools/manual_capture_extra.py
python3 tools/prepare_manual_demo_data.py            # 본체 4모드용 더미 데이터 준비(Qt 불필요)
QT_QPA_PLATFORM=offscreen python3 tools/manual_capture_main_modes.py
```

**주의**: `~/.config/SRIHS/FolderSync.conf`(QSettings 저장 파일)를 먼저 지우지
않으면, 계산기 기록·좌석표 배치·시간표 인증키 등 이전에 실행했던 흔적이
화면에 섞여 나온다. 매번 클린 상태에서 시작해야 매뉴얼용으로 깔끔하다.

## 아직 못 찍은 것 (다음에 보강할 목록)

- 대진표 작성기의 **"오늘 출석 조정"·"학생 추가 배정"** 팝업 — 대진표 탭
  화면은 찍었지만 이 두 버튼을 눌렀을 때 뜨는 다이얼로그는 아직이다.
- 대진표 작성기의 **"참가자 선택" 탭**(체크박스로 학년·반 고르는 화면) —
  명단이 없어 빈 화면만 나와서, 더미 명단을 올린 뒤 다시 찍어야 한다.
- 좌석표 **지정석 서브메뉴를 펼친 상태**(지금은 상위 메뉴 4개 항목까지만
  보이고, "지정석"에 마우스를 올렸을 때 나오는 학생 번호 목록은 안 보인다).
- 나이스 인증키를 **실제로 입력한 상태**의 오늘의 급식/학교 일정(지금은 둘 다
  "인증키를 입력해 주세요" 안내 화면뿐이다) — 네트워크 응답을 가짜로 만들어
  줘야 한다.
- 시간표의 **"전체 과목 다운로드" 진행 중 화면**과 완료 후 경고 팝업.
- 홈 화면에서 **갤럭시폰 사진 옮기기를 Ctrl+Shift+F9로 꺼낸 뒤의 모습**
  (지금 00번 이미지는 이 도구가 숨겨진 기본 상태다).
- **본체 모드의 좌측 트리가 실제로 펼쳐진 상태** — 이 개발 환경(리눅스
  컨테이너)에서는 트리를 펼치면 `/bin`·`/etc`처럼 리눅스 루트 파일시스템이
  그대로 보여서 매뉴얼용으로 못 썼다(실제 Windows 배포 환경에서는
  `C:\Users\...`처럼 자연스럽게 보일 것이다) — 실제 Windows PC에서
  스크린샷을 받아 대체하는 게 가장 깔끔하다.
- 동기화 모드의 **"폴더 하위 구조 보기"·"구조 텍스트 저장"** 결과 화면,
  이동/복사 진행 중 화면.
- 이미지 편집의 **커브 조정 팝오버**, **JPG로 변환** 결과, **이동/복사**
  대상 폴더 선택 화면.
- 중복 찾기의 **이미지 호버 미리보기**(파일에 마우스를 올리면 뜨는 작은
  미리보기), **선택 삭제(휴지통)** 확인 팝업.
- **환경설정 다이얼로그**(즐겨찾기 편집, 캐시 크기, 초기화 버튼 등) — 아직
  한 번도 안 찍었다.

## 새 기능을 추가·수정했을 때 하는 일

1. 화면이 바뀐 미니앱이 있으면, 위 표에서 그 줄의 이미지를 다시 찍어야
   하는지 확인한다(레이아웃·문구·버튼 위치가 바뀌었으면 다시 찍는다).
2. 새로 생긴 팝업·다이얼로그·우클릭 메뉴가 있으면 `manual_capture_extra.py`에
   그 상태를 만드는 코드를 추가하고, 위 표에도 한 줄 추가한다.
3. 새 미니앱이 생기면 `manual_capture_basic.py`의 `cap(...)` 호출을 하나
   추가한다 — 그 미니앱이 아무 조작 없이도 대표성 있는 화면을 보여주면
   `setup` 없이, 빈 상태로 시작하면 `setup` 함수로 샘플 데이터를 채워 넣는다.
4. 스크립트를 다시 돌려서 전체 이미지를 새로 뽑는다(부분적으로만 다시
   찍으면 번호·파일명이 꼬이기 쉽다).
5. 이 문서의 "마지막 갱신" 버전과 이미지 목록 표를 그때 기준으로 고친다.

## 캡처 스크립트를 짤 때 부딪혔던 것들(다음에 또 겪지 않도록)

- **QSettings가 실행 사이에 남는다** — 매번 클린 상태로 시작해야 한다(위
  "사용법" 참고). 특히 계산기 기록·좌석표 저장 배치·인증키가 이전 실행의
  흔적으로 남아 화면에 섞여 나오기 쉽다.
- **`setText()`만으로는 화면이 안 바뀌는 입력칸이 많다** — 대부분
  `editingFinished`나 `returnPressed` 시그널에 실제 처리 로직이 물려 있어서,
  `edit.setText(...)` 다음에 `edit.editingFinished.emit()`(또는 해당 시그널)을
  명시적으로 한 번 더 호출해야 값이 실제로 반영된다.
- **플레이스홀더 텍스트는 실제 입력값이 아니다** — 회색으로 보이는 예시
  글자는 `.text()`가 빈 문자열이다. 실제로 뭔가 계산·번역시키려면 진짜 값을
  `setText()`로 넣어야 한다.
- **탭 위젯은 탭을 안 바꾸면 안의 내용이 안 보인다** — 대진표 작성기처럼
  탭이 있는 화면은 데이터를 다 채워 넣어도 `tabs.setCurrentWidget(...)`을
  안 부르면 엉뚱한(빈) 탭이 찍힌다.
- **오프스크린(`QT_QPA_PLATFORM=offscreen`) 환경에서 `QMenu`(우클릭 메뉴)는
  평범하게 띄우면 화면 캡처에 안 잡힌다** — 부모 창을 그대로 찍으면 메뉴가
  없는 채로 찍힌다. `QMenu.exec`를 오버라이드해서 `show()` 후
  `processEvents()`를 몇 번 돌리고 **메뉴 자신을 `grab()`** 해야 팝업 내용이
  찍힌다(부모 창이 아니라 메뉴 위젯 자체를 찍어야 한다는 뜻).
- **대진표 캔버스 내부 상태(`cells`)를 정식 API 없이 직접 조작하면 앱이
  죽는다**(세그멘테이션 폴트를 실제로 겪었다) — 반드시 `set_event_bracket()`
  같은 정식 메서드로 데이터를 넣어야 한다.
- **본체 모드(동기화·중복 찾기)의 실제 QThread(`ScanThread` 등)를 헤드리스
  환경에서 진짜로 돌리면 이벤트 루프가 영영 멈춘다** — 스레드가 끝났는지
  (`isRunning()`)는 확인되는데 그다음 `processEvents()`에서 멈춰 버렸다.
  동기화는 스레드 대신 `scan()`/`classify()`/`plan_actions()`를 메인
  스레드에서 그냥 순서대로 불러 결과를 직접 화면에 꽂아 넣는 방식으로
  우회했다(반대로 중복 찾기의 `DuplicateScanThread`는 실제로 잘 돌아갔다 —
  같은 QThread라도 스레드마다 다를 수 있으니 매번 먼저 확인해 볼 것).
- **확인 모달(`QMessageBox`)에서 "예" 버튼을 자동으로 누르게 하려고
  `box.clickedButton() is yes_button`처럼 비교하면 실패할 수 있다** —
  PySide6은 같은 C++ 버튼이라도 파이썬 쪽에서 다시 조회할 때마다 새
  래퍼 객체를 만들 수 있어 `is` 비교가 어긋난다. `addButton()`을
  오버라이드해서 그 함수가 **실제로 돌려준 파이썬 객체 자체**를 기억해
  뒀다가 `clickedButton()`에서 그대로 돌려주는 방식으로 우회했다
  (`tools/manual_capture_main_modes.py`의 `_FakeMsgBox` 참고).
- **이 개발 환경(리눅스 컨테이너)에서는 본체 모드의 좌측 트리를 실제로
  펼치면 리눅스 루트 파일시스템(`/bin`, `/etc`...)이 그대로 보인다** —
  Windows 배포 환경과 다르게 보이므로, 트리가 펼쳐진 화면은 이 환경에서
  만들지 말고 실제 Windows PC 스크린샷으로 대체하는 게 낫다.
