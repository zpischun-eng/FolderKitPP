# 확장 FolderKit 통합 개발 계획서 v1

> 상태: **계획 확정 대기 (개발 착수 전)**
> 이 문서 내용이 확정된 후 실제 코드 개발을 시작한다.

---

## 1. 개요

### 1.1 배경
- 기존 `FolderKit_v04` (PySide6): 폴더 구조 복사, 좌우 폴더 동기화, 파일명 일괄 변경 기능 보유
- 기존 `ImageCrop_v01` (Tkinter): 폴더 내 이미지 일괄 크롭 도구
- 두 프로그램을 하나로 통합하되, FolderKit의 기존 UI 톤앤매너(밝고 단순한 라이트 테마, "모드 전환" 구조)를 해치지 않는 것이 최우선 목표

### 1.2 이번 통합의 핵심 결정 사항
1. **GUI 프레임워크는 PySide6로 통합** — ImageCrop의 Tkinter 로직을 PySide6로 재구현(포팅)
2. 이미지 크롭 기능은 향후 기능이 더 늘어날 것을 고려해 **"이미지 편집 모드"**로 명명
3. FolderKit이 이미 가진 **모드 전환 아키텍처(QStackedWidget)** 를 그대로 확장 — 좌측 트리 · 로그 콘솔 · 상태바 · 환경설정 · 히스토리 콤보는 모든 모드가 공유, 중앙 툴바 · 우측 패널 · 하단 실행 버튼만 모드별로 교체
4. 이번 통합에서 함께 처리할 **총 4개 모드**: 동기화 모드(기존) / 파일명 변경 모드(기존, 폴더명 지원 추가) / 이미지 편집 모드(신규) / 중복 파일 찾기 모드(신규)

## 2. 전체 아키텍처

### 2.1 모드 구조
```
FolderKit 메인 윈도우
├─ 공유 영역: 좌측 트리 / 로그 콘솔 / 상태바 / 환경설정 / 최근 작업 히스토리 콤보
└─ 모드별 교체 영역 (중앙 툴바 + 우측 패널 + 하단 실행 버튼)
   ├─ 동기화 모드            (기존, 변경 없음)
   ├─ 파일명 변경 모드        (기존 + 폴더명 수정 지원 추가)
   ├─ 이미지 편집 모드        (신규)
   └─ 중복 파일 찾기 모드     (신규)
```

### 2.2 모드 전환 UI 변경
- (확정) 현재 "파일명 변경 ⇄ 동기화 모드로" 2-way 토글 버튼 → **4개 모드를 각각 나타내는 세그먼트 버튼 그룹**으로 교체. 버튼마다 모드를 한눈에 구분할 수 있는 전용 아이콘(이미지)을 넣고, 마우스 롤오버 시 해당 모드의 이름이 작은 팝업(툴팁 레이어)으로 표시되도록 함
- 모드별 강조색(기존 톤 유지, 서로 겹치지 않게 배정)
  - 동기화: 파랑(기존 `LEFT_MAIN`)
  - 파일명 변경: 주황(기존 `RENAME_MAIN`)
  - 이미지 편집: **보라(신규)**
  - 중복 파일 찾기: **틸/청록(신규)**
- 편집 중인 내용(적용 안 한 이름 변경, 저장 안 한 이미지 편집 등)이 있는 상태로 모드를 바꾸려 할 때 "변경 내용을 버리시겠습니까?" 확인 팝업 — 기존 리네임 모드의 로직을 모든 모드에 공통 적용

## 3. 이미지 편집 모드 (구 이미지 크롭)

### 3.1 레이아웃
- 좌측 트리: 공유 트리 그대로 사용, 폴더 클릭 시 해당 폴더 이미지를 미리보기+썸네일에 로드 (리네임 모드가 파일 목록을 로드하는 방식과 동일한 패턴)
- 우측 패널: 상단 80% 미리보기 / 하단 20% 썸네일 스트립 (ImageCrop 목업 레이아웃 그대로 이식)

### 3.2 크롭 영역 시각화 스펙 (확정)
- 테두리: **점선**(`Qt.DashLine`)
- 꼭짓점(리사이즈 핸들): **작은 원점**(예: 반지름 4~5px 채워진 원)
- 영역 밖 어둡게 처리하는 기존 목업 방식은 유지

### 3.3 중앙 툴바 (변경)
- ~~밝기 슬라이더~~ **제외**
- ~~회전 슬라이더~~ **제외**
- 유지: 크롭 비율 콤보(원본/1:1/4:3/16:9/자유), 기준 콤보(긴 변/짧은 변/픽셀 지정)
- 추가: **커브(Curve) 버튼**

### 3.4 레이어 커브 기능 (신규, 우선 적용 범위)
- `ImageState`에 커브 필드 1개 추가 (RGB 각 채널 포인트 리스트, 이미지별 완전 독립 — 기존 크롭/적용 원칙과 동일)
- 커브 버튼 클릭 → **미리보기 이미지 우측 상단에 팝오버 레이어**로 커브 편집 패널이 뜸: 그래프 위에서 클릭으로 포인트 추가, 드래그로 조정 (커스텀 `QWidget.paintEvent` 기반 그래프). 패널 안의 "적용" 버튼을 누르면 커브가 확정되며 팝오버는 자동으로 사라짐
- 미리보기에 실시간 반영, 배지는 붙지 않음 → 기존과 동일하게 "적용" 눌러야 확정
- **"이 폴더의 모든 이미지에 이 커브 적용"** 일괄 적용 버튼 추가 — 폴더 단위 배치 색보정 요구를 충족
- 여러 조정(밝기/회전/커브)을 쌓는 진짜 "레이어 스택" 구조는 이번 범위에 포함하지 않음. 필요성이 확인되면 이후 버전에서 확장

### 3.5 뷰어 단축키 이동/복사 (FastStone 방식 채택)
- 단축키: **M = 이동**, **C = 복사**
- 동작 흐름:
  1. 미리보기(뷰어)에서 M 또는 C를 누르면, 우측 패널이 (숨겨져 있던) **폴더 트리 화면**으로 전환된다. 이때 별도 팝업 창을 새로 띄우지 않고, 기존 동기화 모드에서 쓰던 우측 트리 컴포넌트를 이미지 편집 모드 우측 패널의 내부 스택(미리보기/썸네일 ↔ 대상 폴더 트리)으로 재사용한다.
  2. 사용자가 마우스로 대상 폴더를 탐색한 뒤 **Enter** 또는 **마우스 우클릭**으로 폴더를 지정하면, 눌렀던 단축키(M/C)에 해당하는 이동 또는 복사가 즉시 실행된다.
  3. 실행 후 우측 패널은 자동으로 미리보기+썸네일 화면으로 복귀하고, 다음 이미지로 포커스가 넘어간다(FastStone의 동작 방식과 동일).
  4. **Esc**를 누르면 아무 동작 없이 미리보기 화면으로 되돌아간다.
  5. **(확정)** 이후 다른 이미지에서 다시 M 또는 C를 누르면, 직전에 지정했던 대상 폴더가 이미 선택된 상태로 우측 트리가 표시된다. 이 상태에서 바로 **Enter**만 누르면 별도 탐색 없이 즉시 이동/복사가 실행되고 미리보기 화면으로 복귀한다. 다른 폴더로 바꾸고 싶으면 트리에서 새로 탐색해서 선택하면 된다.
- 상태바에 현재 어떤 모드(이동 대상 선택 중 / 복사 대상 선택 중)인지 안내 문구 표시

### 3.6 데이터 모델 변경 요약
- `ImageState`: 크롭 영역(rect), 크롭 비율, **커브 포인트(R/G/B)** — 밝기/회전 필드는 제외

## 4. 파일명 변경 모드 확장 — 폴더명 수정 지원

- 현재는 파일명만 대상 → **폴더명도 정규식/찾아바꾸기·접두사 추가 대상에 포함**
- 목록 구성: **파일 목록이 먼저 나오고, 그 다음에 서브 폴더 목록이 이어서 나타남** (사용자 요구사항 그대로 반영)
- 폴더 항목은 파일 항목과 시각적으로 구분: **(확정) 이름 맨 앞에 대표 아이콘을 붙여서 구분** — 파일 항목은 파일 아이콘, 폴더 항목은 폴더 아이콘
- **(확정) 일괄 적용(찾아바꾸기/정규식 등) 실행 시**: 팝업 창으로 "폴더명도 포함해서 변경하시겠습니까?"를 먼저 확인하고, 포함을 선택하면 동일한 변경 규칙을 폴더명에도 함께 적용
- **(확정) 변경 실패 시**: 팝업 창으로 실패 알림 메시지 표시(어떤 항목이 왜 실패했는지 포함)
- 폴더명 변경 시 유의점:
  - 하위 파일/폴더 전체 경로에 영향을 미치므로 파일명 변경보다 되돌리기가 훨씬 어려움 → 실행 전 확인 팝업을 파일명 변경보다 강하게(변경될 폴더 목록을 명시적으로 보여주는 미리보기) 적용
  - 기존 v03의 "다른 프로그램에서 사용 중이라 이름 변경 실패" 처리 로직을 폴더명 변경에도 동일하게 적용, 실패 시 위 알림 팝업으로 안내

## 5. 신규 모드: 중복 파일 찾기

### 5.1 목적
- 선택한 폴더(+하위 폴더 전체)에 포함된 모든 파일을 대상으로, **파일명이 아닌 실제 파일 내용의 동일성**을 기준으로 중복을 판별
- 기존 사용해오던 Duplicate Finder류 프로그램을 대체하는 것이 목표

### 5.2 판별 알고리즘 (제안)
1. 1차: 파일 크기로 그룹화 (크기가 다르면 절대 같은 파일이 아니므로 빠르게 걸러냄)
2. 2차: 크기가 같은 그룹 내에서 파일 앞부분 일부(예: 앞 4~64KB)의 해시로 1차 후보 압축
3. 3차: 1·2차를 통과한 후보끼리만 전체 파일 해시(MD5 또는 xxhash) 비교로 최종 확정
- 대용량 폴더 스캔은 기존 `ScanThread`/`SyncThread`와 같은 패턴으로 **백그라운드 스레드 + 진행률 표시(BusyOverlay 재사용)** 로 처리, 중간 취소 가능하도록 구현

### 5.3 UI 구성
- 좌측: 검사 대상 폴더 선택 (다중 폴더 선택 필요 — 기존 좌측 트리는 단일 선택 구조이므로 확장 필요, 다른 모드에는 영향 없도록 격리)
- 우측 패널: 중복 그룹별 목록 — 그룹 헤더(대표 파일명/크기/개수), 하위에 각 파일의 실제 경로 + 체크박스
- 하단 실행 버튼: 선택 파일 **삭제**(휴지통 이동, 기존 `send2trash` 재사용) 또는 **다른 폴더로 이동**
- (향후 확장 옵션) 그룹당 1개만 남기고 나머지를 자동 선택하는 편의 규칙은 이번 범위에서는 제외, 필요 시 다음 버전 논의

### 5.4 신규 데이터 모델
- `DuplicateGroup`: 파일 크기, 해시값, 그룹에 속한 파일 경로 리스트

## 6. 개발 우선순위 (단계 제안)

| 단계 | 내용 |
|---|---|
| 1단계 | 프레임워크 포팅: 이미지 편집 모드 뼈대(크롭 + 점선/원 핸들) PySide6로 구현, 모드 전환 UI를 4-way로 확장 |
| 2단계 | 레이어 커브 기능(포인트 1개 필드 + 폴더 일괄 적용) 추가 |
| 3단계 | 뷰어 단축키 이동/복사(FastStone 방식) 추가 |
| 4단계 | 파일명 변경 모드에 폴더명 지원 + 서브 폴더 목록 표시 추가 |
| 5단계 | 중복 파일 찾기 신규 모드 추가 |

## 7. 잠재적 문제점 및 대응 방안 (채택 확정)

> 아래 항목은 문서 내 제안된 대응 방안을 그대로 채택하여, 관련 섹션의 설계에 반영함.

- **포팅 리스크**: Tkinter Canvas의 마우스 드래그 이벤트 처리 방식과 Qt(`QGraphicsView`/`QWidget.paintEvent` + `mousePressEvent` 등)의 이벤트 처리 방식이 달라서, 크롭 영역 드래그/리사이즈 인터랙션 로직은 그대로 옮기는 게 아니라 사실상 다시 작성해야 함
- **모드 전환 복잡도 증가**: 2-way 토글에서 4-way로 늘어나면서 "적용 안 한 변경사항이 있을 때 모드 전환 시 확인" 같은 기존 로직을 모든 모드 조합에 대해 일관되게 처리해야 함(상태 관리가 단순 토글 → 상태 머신에 가까워짐)
- **이미지 편집 모드 우측 패널의 중첩 스택**: 미리보기/썸네일 ↔ 대상 폴더 트리 전환 시, 전환 도중 선택돼 있던 이미지·크롭 상태가 흐트러지지 않도록 상태 보존 필요, Esc 취소 시 정확히 원래 화면으로 복귀해야 함
- **폴더명 변경의 파급력**: 파일명 변경보다 되돌리기가 어렵고 하위 경로 전체에 영향 — 확인 절차를 파일명 변경보다 강화할 필요
- **중복 파일 찾기 성능**: 파일 수가 많거나 대용량 파일이 많은 폴더는 해시 계산에 시간이 걸림 — 진행률 표시와 취소 기능이 사실상 필수
- **중복 파일 삭제 시 실수 방지**: 같은 파일이 여러 개 나열될 때 사용자가 실수로 전부 선택하지 않도록(즉, 원본이 하나도 안 남는 상황) 안내나 방어 로직 필요
- **다중 폴더 선택 UI**: 중복 찾기 모드에서만 좌측 트리를 다중 선택으로 확장해야 하는데, 동기화/리네임/이미지 편집 모드의 단일 선택 동작에 영향이 가지 않도록 구현을 격리해야 함
- **커브 편집 위젯**: 기존에 없던 완전히 새로운 커스텀 그래프 컴포넌트라 다른 항목보다 구현 난이도가 높은 편

## 9. UI 통일 리디자인 (v22~) — "탐색기 리본" 콘셉 채택

4-way 모드(동기화/파일명 변경/이미지 편집/중복 파일 찾기)가 각기 다른 독립
프로그램에서 이식되며 화면 UI의 통일성을 잃은 문제를 해결하기 위한 리디자인.
전체 구조는 "좌측 폴더 트리가 기준"이라는 FolderKit의 콘셉을 계속 유지한다.

### 9.1 검토한 콘셉 3가지
- **콘셉 A(채택, 1단계)**: 탐색기 리본 — 공통 헤더 바(모드 세그먼트+환경설정+
  새로고침, 항상 같은 위치)와 모드별 액션 바(내용은 다르지만 패널 스타일은
  통일)를 명확히 두 줄로 분리. 좌측 트리·콘솔은 공통 컴포넌트로 통일.
- **콘셉 B(채택, 2단계 — 다음 리디자인 예정)**: 모드 세그먼트를 상단에서
  좌측 트리 옆 세로 아이콘 바(VSCode 액티비티 바 방식)로 이동. "좌측 폴더
  기준"이라는 정체성을 시각적으로 더 강하게 드러낸다.
- **콘셉 C(보류)**: 화면을 트리+결과만 남기고 모드별 옵션을 톱니바퀴 팝오버로
  숨기는 최소화 콘셉. 화면은 가장 깔끔하지만 자주 쓰는 기능까지 클릭이
  늘어나는 단점이 있어 이번 범위에서는 채택하지 않음(단, 자주 안 쓰는
  세부 옵션 한정으로는 부분 적용 여지 있음).

### 9.2 콘셉 A 적용 내역(v22)
- **공통 헤더 바 / 모드별 액션 바 2행 분리**: 기존에는 모드 세그먼트·환경설정·
  새로고침·모드 도구가 한 줄(QHBoxLayout)에 섞여 있어, 모드 도구 길이가
  늘어나면 설정/새로고침 버튼까지 밀리는 것처럼 보였다. 1행(common_row)에
  모드 세그먼트+환경설정+새로고침을 고정하고, 2행(action_bar_frame)에
  모드별 도구(tool_stack)를 감싸는 공통 패널을 두어 항상 같은 높이(50px)·
  여백으로 표시되도록 분리했다.
- **모드별 액션 바 톤 배경**: `_style_action_bar()`가 현재 모드의 옅은 강조색
  (동기화=파랑/파일명변경=주황/이미지편집=보라/중복찾기=틸)으로 패널
  배경·테두리를 갱신 — 내용은 달라도 "지금 이 모드의 도구 영역"임을
  은은하게 보여준다.
- **콘솔 로그를 4개 모드 공통 접이식 컴포넌트로 통일**: 기존에는 이미지 편집
  모드에서만 진행바·로그가 완전히 사라지고 나머지 세 모드는 항상 180px를
  차지해 통일성이 없었다. `_toggle_console()`로 접기/펼치기 가능한 콘솔로
  바꾸고 기본은 접힌 상태로 시작, 4개 모드 전부 동일하게 제공한다. 진행바는
  차지 비용이 작아(18px) 모드와 무관하게 항상 노출한다. 하단 큰 실행 버튼
  행(bottom_stack)만 기존처럼 이미지 편집 모드에서 숨김(적용/저장은 우측
  패널 소형 버튼으로 대체하는 기존 방식 유지).
- **버튼 높이 통일**: 중복 찾기 모드의 하단 실행 버튼(선택 삭제/이동)이 44px로
  다른 모드의 실행 버튼(52px)과 달랐던 것을 52px·글자 14px·모서리 6px로
  통일.

### 9.3 다음 단계(콘셉 B) 예고
- 모드 세그먼트를 상단 공통 헤더 바에서 좌측 트리 옆 세로 아이콘 바로 이동.
- 상단 공통 헤더 바는 환경설정/새로고침만 남기고, 그만큼 확보된 폭을
  모드별 액션 바가 활용하도록 재구성.
- 좌측 트리 폭 계산에 아이콘 바 폭만큼 보정 필요.

### 9.4 콘셉 B 적용 내역(v23)
- **좌측 액티비티 바 신설**: 4개 모드 세그먼트 버튼을 상단 공통 헤더 바에서
  좌측 트리 옆의 세로 아이콘 바(`activity_bar`, 폭 48px)로 이동. 트리 바로
  왼쪽에 모드 전환이 위치하게 되어 "좌측 폴더 트리가 기준"이라는 FolderKit
  콘셉을 시각적으로 더 강하게 드러낸다.
- **환경 설정도 액티비티 바로 통합**: 기존 "환경 설정" 텍스트 버튼을 액티비티
  바 하단의 아이콘 버튼으로 이동. 상단에는 더 이상 별도의 공통 헤더 바가
  없고, 그 자리를 모드별 액션 바(`action_bar_frame`)가 전체 폭으로 활용한다.
- **새로고침 버튼 제거**: "새로고침 (F5)" 버튼을 화면에서 없애고, F5 단축키
  로만 동작하도록 함(사용자 요청 반영) — 자주 쓰는 기능이 아니라는 판단.
- **레이아웃 구조**: `top_area`를 QVBoxLayout에서 QHBoxLayout으로 바꾸고,
  `activity_bar`(좌측 고정폭)와 `content_col`(액션 바+트리/작업영역+하단
  실행버튼을 담는 세로 컬럼)을 나란히 배치하는 구조로 재구성.

### 9.5 세부 다듬기(v24)
- **환경 설정 아이콘 교체**: 액티비티 바 하단의 "환" 텍스트 버튼을 일반적인
  톱니바퀴(gear) 아이콘으로 교체(`make_mode_icon("settings", ...)` 추가,
  다른 모드 아이콘과 동일한 화법 — 흰색 이빨/몸통 + 배지색으로 뚫은 가운데 구멍).
- **좌우 분할 기본 비율 조정**: 동기화 모드는 기존대로 50:50 유지, 그 외

  30:70으로 조정(사용자가 캡처로 제시한 참고 화면 반영).

- `MainWindow.__init__`에서 UI를 만들기 전에 `set_language(cfg.language)`를

## 12. 주소 입력창 재시도 — 헤더 클릭 방식 (v27)

v26에서 시도한 "트리 위에 별도 입력창을 얹는" 방식은 tree_source를 새
컨테이너로 감싸면서, 모드 전환 시 트리를 원래 자리로 되돌리는
`_ensure_tree_source_parent()`("tree_source의 부모는 반드시 self.splitter"라고
가정)와 충돌해 우측 폴더창이 사라지는 버그를 일으켰다(계획서 11절 내역,
v26 롤백). 이번에는 트리 구조를 전혀 건드리지 않는 다른 방식으로 재시도했다.

### 12.1 방식 — 헤더(선택 경로 표시줄) 클릭 → 그 자리를 입력창으로 전환
사용자가 제안한 방식대로, 트리 상단에 항상 떠 있는 "선택 경로 표시줄"
(기존에도 있던 기능 — 폴더 클릭 시 헤더에 전체 경로가 표시됨)을 클릭하면
그 자리를 그대로 덮는 텍스트 입력창으로 바뀌어 경로를 직접 타이핑할 수
있다. Enter를 누르면 그 폴더로 이동하고, Esc를 누르거나 다른 곳을
클릭하면(포커스 이탈) 아무 일도 없었던 것처럼 원래 표시로 되돌아간다.
탐색기 주소창의 동작과 사실상 동일하다.

### 12.2 v26과 다른 점 — 왜 이번엔 안전한가
- tree_source/tree_dest를 감싸는 새 컨테이너를 전혀 만들지 않는다. 입력창
  (`path_edit_source`/`path_edit_dest`)은 트리의 `QHeaderView` 위에 얹는
  자식 위젯일 뿐, 트리 자체의 부모-자식 구조(스플리터 직속)는 그대로다.
- 따라서 `_ensure_tree_source_parent()`가 어떤 가정을 하든 전혀 영향을
  받지 않는다 — 애초에 이 함수가 관여하는 계층 구조를 건드리지 않기 때문.
- 헤드리스 회귀 테스트에 "모드를 여러 번 순환한 뒤에도 splitter의 pane
  개수가 정확히 2개, tree_source의 부모가 splitter 그대로인지"를 명시적
  으로 검증하는 항목을 추가해, 같은 종류의 버그가 재발하면 바로 잡아내도록 함.

### 12.3 구현 요약
- `_make_tree()`: `header().setSectionsClickable(True)` + 헤더를 부모로 하는
  `QLineEdit` 오버레이 생성(초기 숨김) + `sectionClicked` 시그널 연결.
- `_show_path_edit()`: 헤더 영역과 정확히 같은 크기·위치로 입력창을 띄우고
  현재 선택 경로를 채워 넣은 뒤 포커스.
- `_go_to_typed_path()`: 입력 경로를 정규화 → `model.index(path)`로 인덱스
  획득 → 조상 폴더 전개 → 스크롤·선택 → 트리를 직접 클릭했을 때와 동일한
  `on_source_clicked()`/`on_dest_clicked()` 호출.
- `eventFilter()`에 Esc 키·포커스 아웃 처리를 추가해 취소 동작을 구현.

## 13. 경로 이동 시 스크롤 위치 보정 (v28)

v27의 헤더 클릭 경로 입력 기능에서, 깊은 경로로 이동하면 조상 폴더들이
모두 펼쳐지긴 하지만 화면이 그 위치까지 스크롤되지 않아 사용자가 직접
스크롤을 내려야 목표 폴더를 찾을 수 있는 문제가 있었다.

### 13.1 원인
`QFileSystemModel`은 폴더 내용을 백그라운드 스레드에서 비동기로 읽어와
채워 넣는다. `expand()`를 호출한 직후 곧바로 `scrollTo()`를 부르면, 아직
다 채워지지 않은 상태를 기준으로 스크롤 위치가 계산되어 목표 폴더가
화면 맨 아래로 밀리거나 엉뚱한 위치에 남는 경우가 있었다(재현 테스트로
직접 확인 — 한 번의 스크롤 직후 측정하면 위치가 어긋나고, 프레임을 몇 번
더 진행하며 반복 보정해야 정확한 위치로 수렴함).

### 13.2 해결 — 레이아웃이 안정될 때까지 스크롤을 반복 보정
`_scroll_tree_to_top()`을 추가해, `doItemsLayout()`(레이아웃 즉시 확정) +
`scrollTo(idx, PositionAtTop)`(목표 폴더를 맨 위로) 세트를 `QTimer.
singleShot(30, ...)`으로 8회 정도 짧은 간격을 두고 반복한다. 배경에서
폴더 내용이 마저 채워지는 동안에도 매번 다시 위치를 맞춰주기 때문에,
최종적으로는 목표 폴더가 확실히 트리 맨 위에 오도록 수렴한다. UI 스레드를
막지 않는 짧은 타이머 체인이라 사용자 입장에서는 이동과 동시에 자연스럽게
맨 위로 스크롤된 것처럼 보인다.

## 14. 롤오버 힌트 폰트 통일 + 하단 버튼 축소 + 콘솔 공간 확보 (v29)

### 14.1 롤오버 힌트 글자 크기가 버튼마다 달라 보인 원인
실제로 다른 게 맞았다. `btn_copy`(좌측 구조를 우측으로 복사)는 스타일시트에
`font-size:14px`, `btn_sync`(좌·우 폴더 동기화)는 `font-size:16px`가 각각
버튼 글자 크기로 지정되어 있었는데, Qt의 롤오버 힌트(QToolTip)는 별도로
스타일을 지정하지 않으면 그 힌트를 띄운 버튼 자신의 폰트를 그대로 물려받는
동작을 한다. 그래서 버튼 글자 크기가 다르면 힌트 글자 크기도 따라서
달라져 보였다 — 착각이 아니라 실제 차이였다.

**해결**: `app.py`의 `apply_fixed_palette()`에서 `QApplication.setStyleSheet()`로
`QToolTip{font-size:12px; ...}`를 앱 전체에 한 번 지정했다. 개별 버튼의
글자 크기(라벨 자체의 디자인)는 그대로 두되, 롤오버 힌트만큼은 어떤
버튼 위에서 띄우든 항상 12px로 고정되어 통일된다.

### 14.2 하단 실행 버튼 세로 크기 축소 (52px → 40px)
동기화 모드의 "좌측 구조를 우측으로 복사" · "좌·우 폴더 동기화", 파일명
변경 모드의 "이름바꾸기(적용)", 중복 찾기 모드의 "선택 삭제" · "선택 항목
이동" — 이 5개 버튼의 높이를 좌측 액티비티 바의 환경 설정 버튼(40×40)과
같은 40px로 맞췄다. 그만큼 위쪽 트리/작업 영역이 넓어졌다.

### 14.3 콘솔 로그를 "드래그로 크기 조절 가능한" 영역으로 전환
기존에는 콘솔 로그가 고정 높이(180px)라 펼쳐도 딱 그만큼만 보였다.
[v29]부터는 위(작업 영역)와 아래(콘솔)를 세로 `QSplitter`로 묶어, 콘솔을
펼친 뒤 그 경계선을 마우스로 드래그해서 원하는 만큼 자유롭게 늘리거나
줄일 수 있다. 콘솔을 펼칠 때는 일단 220px 정도로 잡아주고, 그 다음부터는
사용자가 원하는 크기로 직접 조절하면 된다 — 특정 고정값에 묶이지 않는
근본적인 해결책이다. 하단 실행 버튼 축소분(52→40, 12px)까지 더하면 콘솔이
필요할 때 확보할 수 있는 공간은 이전보다 늘어난다.

### 14.4 "폴더 하위 구조 보기" 시 콘솔 자동 노출
"폴더 하위 구조 보기" 결과는 콘솔 로그에만 출력되는데, 콘솔이 접혀 있으면
버튼을 눌러도 아무 일도 없는 것처럼 보였다. `_ensure_console_visible()`을
추가해 `show_tree_text()` 실행 직전에 콘솔이 접혀 있으면 자동으로 펼치도록
했다.

## 15. 버튼 정렬 보정 + 헤더 입력창 핵심 버그 수정 (v30)

### 15.1 환경 설정 버튼 세로 정렬
좌측 액티비티 바(activity_bar)의 위아래 여백이 8px, 우측 콘텐츠 컬럼
(content_col)은 0px로 서로 달라, 환경 설정 버튼(액티비티 바 맨 아래)과
하단 실행 버튼(콘텐츠 컬럼 맨 아래)의 높이가 8px씩 어긋나 보였다.
액티비티 바 여백을 0으로 맞춰 두 버튼 그룹의 하단이 정확히 일치하도록
수정했다.

### 15.2 헤더 입력창(주소창) 핵심 버그 — 원인과 수정
**증상**: 우측 헤더를 클릭→경로 입력→이동은 되지만, 이후 좌·우 어느 쪽
트리에서 폴더를 평범하게 클릭해도 헤더가 갱신되지 않고, 입력창이 계속
입력 가능한 상태로 남아있는 것처럼 보였다.

**원인**: `_make_tree()`가 `side`값을 "L이면 좌측, 아니면 전부 우측"으로
처리하고 있었는데, 이미지 편집 모드의 "이동/복사 대상 트리"가 같은 함수를
`side="I"`로 재사용하면서 이 조건에 걸려, 화면에 보이지도 않는 그 트리의
입력창으로 `self.path_edit_dest`(우측 트리의 진짜 입력창)를 덮어써버리고
있었다. 이후 우측 헤더를 클릭하면 실제로는 엉뚱한(보이지 않는) 위젯이
열리는 것이었고, 그 결과 헤더가 갱신되지 않고 입력 상태가 남은 것처럼
보이는 증상으로 나타났다. `shiboken6.getCppPointer()`로 두 입력창의 실제
C++ 포인터를 비교해 "우측 입력창의 진짜 부모가 화면에 보이는 우측
트리가 아니다"라는 사실을 확인해 원인을 특정했다.

**수정**: `_make_tree()`에서 이 경로 입력 기능을 `side`가 "L" 또는 "R"일
때만 만들도록 명확히 제한(`if side in ("L", "R"):`)해, "I" 트리가 더 이상
`path_edit_source`/`path_edit_dest`를 건드리지 않도록 했다.

**추가 방어 조치**: 좌·우 입력창이 동시에 열려 있을 수 있는 상태(Enter를
누르지 않고 반대쪽 헤더를 클릭하는 경우)를 없애기 위해, 하나를 열기 전에
다른 하나가 열려 있으면 먼저 닫도록 상호 배타 처리를 추가했다.

**검증**: `QTest.mouseClick`으로 실제 마우스 클릭까지 재현해 "우측 헤더
클릭 → 입력 → Enter → 이동 → 정상 클릭 → 헤더 갱신 → 좌측도 동일 →
모드 전환 후에도 정상" 전체 시나리오가 정상 동작함을 확인했다.

## 16. 콘솔 로그를 닫을 때 트리 영역 높이 복원 (v31)

[v29]에서 콘솔 로그를 고정 높이 대신 드래그 가능한 세로 스플리터(아래쪽
칸)로 바꾸면서, **펼칠 때만** 적당한 높이(220px)로 스플리터 크기를
다시 잡아주고 **닫을 때는 별도 처리를 하지 않았다**. 그 결과 콘솔을 펼쳤다
닫으면, 스플리터는 여전히 마지막으로 펼쳤던 크기(예: 220px)를 콘솔 칸에
그대로 남겨둔 채 그 안의 로그(QTextEdit)만 숨겨서, 콘솔 토글 줄 아래로
텅 빈 공백만 남고 정작 트리 영역은 넓어진 공간을 돌려받지 못하는 어색한
모습이 되었다.

**수정**: `_toggle_console()`을 접는 방향으로 호출될 때도 스플리터 크기를
명시적으로 되돌리도록(`setSizes([total, 0])`) 했다. 콘솔 칸의 실제 최소
크기(토글 줄만큼)로 자동 수렴하면서, 위쪽 트리 영역이 다시 거의 전체
높이를 차지해 최초 실행 화면과 동일한 모습으로 돌아온다.

## 17. 콘솔 완전 접힘 버그 수정 + 중복찾기 개선 + 단축키 도움말/추가 (v32)

### 17.1 콘솔이 일부 모드에서 아예 열리지 않던 버그
[v31]에서 "콘솔을 닫으면 트리 영역이 원래대로 돌아와야 한다"는 문제를
고치면서 `main_vsplit.setSizes([total, 0])`으로 콘솔 칸 크기를 0으로
되돌리도록 했는데, 이 칸이 `setCollapsible(1, True)`(완전히 접힘 허용)
상태였던 탓에 정말로 0까지 줄어들어 **콘솔 로그 토글 버튼 자체가 화면에서
사라져버리는** 새로운 문제가 생겼다. 중복 찾기 모드에서 콘솔을 아예 열
방법이 없어지고, 이후 동기화 모드로 돌아와도 마찬가지였던 것이 이 때문.

**수정**: `setCollapsible(1, False)`로 바꿔, 콘솔 칸이 아무리 작아져도
최소한 토글 버튼 한 줄만큼의 높이는 항상 유지하도록 했다. 0을 요청해도
Qt가 알아서 최소 크기로 clamp해주므로, [v31]에서 의도했던 "닫으면 원래
크기로 돌아온다"는 동작은 그대로 유지된다.

### 17.2 중복 찾기 — 전체 폴더 해제
기존 "목록 초기화" 버튼이 이미 등록된 검사 대상 폴더를 전부 지우는
기능을 하고 있었으나(코드상 `dupfind_clear_targets()`), 이름이 그
기능을 명확히 전달하지 못했고 마침 콘솔 버그(17.1)까지 겹쳐 사용자가
동작 결과(콘솔 로그)를 확인할 수 없어 "해제할 방법이 없다"고 느꼈다.
버튼 이름을 "전체 폴더 해제"로 명확히 바꾸고, 폴더를 추가하거나 전체
해제할 때 콘솔이 접혀 있으면 자동으로 펼쳐 결과를 바로 확인할 수 있게
했다(`_ensure_console_visible()` 호출 추가).

### 17.3 단축키 도움말 다이얼로그
환경설정 다이얼로그에 "단축키 보기" 버튼(HelpRole)을 추가. 누르면
`ShortcutsDialog`가 열려 공통 단축키(F5)와 이미지 편집 모드 전용
단축키(Space/Ctrl+S/Ctrl+Z/Ctrl+Y/M/C/S/Esc)를 한 화면에서 확인할 수
있다. 3개 언어 모두 지원.

### 17.4 커브 단축키(S) 추가
이미지 편집 모드에서 커브 창을 즉시 여는 단축키로 **S**를 추가했다.
기존 단축키(Space/Ctrl+S/Ctrl+Z/Ctrl+Y/M/C/Esc)와 겹치지 않는 단순한
키를 골랐다.

## 18. 디자인 다듬기 — 파일명 변경 아이콘 교체 + 이중 테두리 제거 (v33)

### 18.1 파일명 변경 모드 아이콘 교체
기존 아이콘은 연필처럼 보이는 사각 도형 하나였는데, 무엇을 그린 건지
알아보기 어렵다는 의견이 있었다. 45도로 기울인 연필 몸통(흰색 촉 +
테두리만 있는 몸통) 끝에 사각 지우개(흰색 채움)를 붙인 모양으로 다시
그려, "이름을 쓰고 지운다"는 의미가 한눈에 들어오도록 했다. 다른 모드
아이콘과 동일한 화법(강조색 원형 배지 + 흰색 글리프)은 그대로 유지.

### 18.2 액션 바 내부 이중 테두리 제거
각 모드의 액션 바(`action_bar_frame`)는 모드별 강조색으로 둥근 테두리를
그리는데, 그 안에 놓인 `QLineEdit`/`QComboBox`(파일명 변경의 찾기·바꾸기·
접두사 입력창, 이미지 편집의 크롭 비율·기준 콤보)는 Qt 기본(Fusion)
스타일의 진회색 테두리를 그대로 쓰고 있어, 두 테두리가 가까이 붙어
"테두리 안에 또 테두리"처럼 겹쳐 보였다.

`styles.py`에 `FLAT_INPUT_STYLE(accent)` 헬퍼를 추가해, 평소엔 테두리를
투명하게 감추고 포커스가 있을 때만 그 모드의 강조색으로 얇게 보이도록
통일했다. 대상: `find_input`/`replace_input`/`prefix_input`(파일명 변경,
주황), `combo_ratio`/`combo_basis`(이미지 편집, 보라). 동기화 모드의
`combo_history`는 이미 자체적으로 옅은 회색 테두리를 쓰고 있어 상대적으로
덜 두드러졌던 데다, 드롭다운 화살표를 직접 그리는 등 스타일이 더
정교하게 짜여 있어 이번 범위에서는 그대로 두었다.

## 19. 이중 테두리 — 진짜 원인과 완전한 수정 (v34)

[v33]에서 액션 바 안의 QLineEdit/QComboBox에 `FLAT_INPUT_STYLE`을 적용했지만,
스크린샷으로 다시 확인해보니 여전히 라벨("찾기:", "크롭 비율:" 등) 하나하나
에 작은 테두리 상자가 남아있었다. 원인을 다시 파고든 결과 진짜 원인을
찾았다.

**원인**: `action_bar_frame`(액션 바 전체를 감싸는 `QFrame`)의 스타일시트가
`QFrame{background-color:...;border:1px solid ...;border-radius:6px;}`
형태로, 타입 셀렉터 `QFrame`을 그대로 사용하고 있었다. 그런데 Qt에서는
**`QLabel`이 클래스 계층상 `QFrame`을 상속**한다(레이블에 프레임 테두리를
줄 수 있도록 설계된 역사적 구조). 그 결과 이 스타일 규칙이 액션 바 자신
뿐 아니라, 그 안에 있는 **모든 QLabel에도 그대로 적용**되어 "찾기:",
"→ 바꾸기:", "크롭 비율:", "기준:" 같은 라벨 하나하나가 작은 배경+테두리
박스를 갖게 되었다 — 이것이 사용자가 본 "테두리 안에 또 테두리"의 정체.

**수정**: `action_bar_frame`에 `setObjectName("action_bar_frame")`을 지정하고,
스타일시트 셀렉터를 `QFrame#action_bar_frame{...}`으로 좁혔다. 이렇게
ID 셀렉터를 쓰면 이 특정 위젯 인스턴스에만 스타일이 적용되고, 같은 타입
계층(QFrame 상속 관계)에 있는 자식 QLabel들에는 더 이상 영향을 주지 않는다.
같은 패턴(`위젯타입{...}` 형태로 자식까지 의도치 않게 물들이는 스타일)이
다른 곳에도 있는지 전수 점검한 결과, 나머지는 이미 구체적인 타입
(`QTreeWidget`, `QLineEdit` 등 QLabel과 상속 관계가 없는 타입)이거나
선택자 없이 위젯 인스턴스에 직접 지정된 형태라 문제가 없음을 확인했다.

## 20. 경로 이동 시 인덱스 무효화로 인한 선택 실패 수정 (v35)

실제 사용 중 발견된 문제: 탐색기 주소창에서 복사한 경로를 헤더 입력창에
붙여넣고 이동하면, 헤더에 표시되는 텍스트는 정상적으로 그 경로로
바뀌는데 정작 트리에서는 이전에 선택했던 폴더(예: 다른 드라이브)가
그대로 강조 표시된 채 남아있는 경우가 있었다.

**원인**: `_scroll_tree_to_top()`이 [v28]에서 도입한 "레이아웃이 안정될
때까지 몇 프레임에 걸쳐 반복 스크롤" 로직에서, 맨 처음 한 번만 구한
`QModelIndex`를 8번의 재시도 내내 그대로 재사용하고 있었다.
`QFileSystemModel`은 폴더 내용을 배경 스레드에서 비동기로 계속 채워
넣는데, 그 사이 모델 내부 구조가 갱신되면서 예전에 구해둔 인덱스가
무효화될 수 있다(특히 반응 속도가 다른 실제 Windows 환경에서 더 잘
드러남). 인덱스가 무효화된 뒤에는 `setCurrentIndex()`/`scrollTo()`가
조용히 아무 효과도 내지 못해, 화면에는 이전 선택 상태만 남는다. 반면
헤더 텍스트는 이동 성공 직후 한 번(`on_source_clicked`/`on_dest_clicked`)
만에 즉시 갱신되므로 텍스트만 맞고 트리는 안 따라가는 것처럼 보였다.

**수정**: `_scroll_tree_to_top()`이 매 재시도마다 `model.index(path)`로
인덱스를 다시 구하도록 변경했다. 이제 재시도 루프의 모든 단계가 "그
순간 실제로 유효한" 인덱스를 기준으로 동작해, 모델이 비동기로 계속
갱신되더라도 최종적으로는 반드시 목표 폴더가 선택·스크롤된다.

## 21. 맥(Mac) 파일명 자모 분리 문제 — "이름 정규화" 기능 추가 (v36)

### 21.1 현상 설명 — 버그가 아니라 인코딩 정규화 방식 차이
맥에서 저장한 한글 파일명은 흔히 "자모 분리"(유니코드 NFD, Normalization
Form Decomposed) 방식으로 저장된다 — "가"라는 한 글자가 초성(ㄱ)과
중성(ㅏ)이라는 별개의 코드 두 개로 나뉘어 저장되는 식이다. 윈도우와
대부분의 다른 프로그램은 한 글자를 코드 하나로 합쳐 저장하는 NFC
(Normalization Form Composed) 방식을 기본으로 쓰기 때문에, 윈도우
탐색기는 이 분리된 코드들을 제대로 합쳐 보여주지 못해 글자가 깨진
것처럼(반각 문자 등) 보인다.

FolderKit(Qt 기반)은 화면에 글자를 그릴 때 분리된 코드도 알아서 조합해
정상적으로 보여주기 때문에, 같은 파일이 FolderKit에서는 멀쩡하게 보인다.
문제는 **디스크에 저장된 실제 이름 자체는 여전히 분리된(NFD) 상태**라는
점 — FolderKit 화면만 봐서는 "고칠 게 없어 보이지만", 실제로는 탐색기를
비롯한 다른 프로그램에서 계속 깨져 보이고, 향후 다른 곳(압축·업로드 등)
에서도 같은 문제가 반복된다.

### 21.2 해결 — "이름 정규화(Mac 호환)" 버튼
파일명 변경 모드에 새 버튼을 추가했다. 현재 불러온 폴더의 파일/폴더
이름 중 유니코드 NFC 형태가 아닌 것(대표적으로 맥의 NFD)을 찾아, 실제
파일 시스템상의 이름 자체를 NFC로 바꿔준다(`unicodedata.normalize
("NFC", name)`). 이렇게 하면 탐색기를 포함한 모든 프로그램에서 정상
적으로 보이게 된다.

- 이미 NFC인 파일은 건드리지 않는다.
- 바꾸려는 이름이 이미 존재하면(충돌) 건너뛰고 콘솔에 남긴다.
- 임시 이름으로 한 번 거쳐 가는 2단계 rename으로 처리해, 대소문자만
  다른 경우 등 파일 시스템에 따라 생길 수 있는 충돌을 피한다.
- 처리 결과(고친 개수·건너뛴 개수·실패 개수와 각 파일명)를 콘솔 로그에
  자동으로 펼쳐서 남기고, 완료 후 요약 대화상자를 띄운다.
