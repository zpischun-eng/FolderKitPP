# FolderKit 확장 개발 변경 이력

계획서(`PLAN_v1.md`) 확정 이후 실제 개발 과정에서 반영된 변경 사항을 버전별로 기록한다.

---

## v05 — 1단계: 프레임워크 통합 + 이미지 편집 모드 신설

계획서 1단계 범위로 최초 구현.

- **프레임워크 통합**: 기존 `ImageCrop_v01.py`(Tkinter)의 이미지 편집 기능을 PySide6로
  재구현하여 FolderKit의 "모드 전환" 구조(동기화 ↔ 파일명 변경)에 세 번째 모드로 편입.
- **모드 전환 UI**: 기존 2-way 토글 버튼을 3-way 세그먼트 버튼(아이콘 + 롤오버 툴팁)으로 교체.
- **이미지 편집 모드 신설**:
  - 좌측 트리에서 폴더 선택 → 썸네일 스트립 + 미리보기 로드
  - 크롭 영역: 테두리 점선(`Qt.DashLine`) / 꼭짓점 작은 원형 핸들
  - 크롭 비율(원본/1:1/4:3/16:9/자유) · 기준 콤보 (밝기·회전 슬라이더는 계획서 확정에 따라 제외)
  - 레이어 커브(전 채널 공통 LUT 1개) — 우측 상단 팝오버로 편집
  - 뷰어 단축키 M(이동)/C(복사) — FastStone 방식 채용: 팝업 대신 우측 트리를 그 자리에서
    보여주고 Enter/우클릭으로 대상 폴더 지정
- **파일명 변경 모드 확장**: 폴더명 변경 지원 추가, 파일 목록 다음 서브 폴더 목록 표시,
  파일📄/폴더📁 아이콘 구분, 일괄 적용 시 폴더명 포함 여부 확인, 실패 시 알림 팝업.
- 4번째 모드(중복 파일 찾기)는 이번 버전에 포함하지 않음 — 계획서 5단계로 이월.

### v05 버그 수정 (스크린샷 피드백 반영)
- 적용 시 크롭+커브 결과 이미지로 미리보기 화면이 가득 차도록 수정 (기존엔 크롭 오버레이만 유지).
- 커브 그래프가 부드러운 곡선으로 그려지고, 드래그 즉시 밝기 효과가 실시간 반영되도록 수정
  (기존엔 저장 시점에만 파일에 반영되고 화면엔 전혀 반영되지 않던 문제).
- 크롭 선택 영역이 "적용" 없이도 즉시 상태에 저장되어, 다른 썸네일로 이동했다 돌아와도 유지되도록 수정.
- 적용된 이미지에 썸네일 배지(점) 표시.
- 이미지 편집 모드에서는 하단 진행바·로그 콘솔·큰 적용/저장 버튼을 숨기고, 좌측 트리 + 우측
  뷰어/썸네일만 남기도록 레이아웃 축소. 적용/저장은 소형 버튼으로 옮기고, 그 옆에
  이미지명·크기·용량 정보 바를 신설.
- 폴더 구조 보기의 "최근 작업 히스토리" 정렬 기준을 최다 선택 → 최근 선택 우선으로 변경.

## v07 — 적용 상태 지속성 버그 수정 + 커브 알고리즘 1차 개선

- **적용(배지) 상태가 사라지는 버그 수정**: 크롭 영역이나 커브를 다시 조정할 때마다 자동으로
  적용/저장 배지를 취소하던 로직을 제거. 이제 배지는 **오직 저장(Save)했을 때만** 사라진다.
- **커브 곡선 품질 개선(1차)**: 국소 보간(Catmull-Rom)의 경계 구간에서 이웃 점을 단순 복제하던
  방식을, 반사(reflection) 기반 가상 제어점 방식으로 교체 — 시작 지점이 살짝 휘어 보이던 문제 완화.

## v08 — 커브 알고리즘 전역 보간 전환 + 버그 수정 + 소스 모듈화

### 커브: 자연 삼차 스플라인(Natural Cubic Spline)으로 교체
v07의 Catmull-Rom은 국소 보간이라 중간에 점을 추가하면 양쪽 구간이 미세하게 분절되어 보이는
한계가 있었다. 포토샵 커브와 동일하게, 전체 포인트를 하나의 연립방정식으로 동시에 풀어 전
구간이 매끄럽게 이어지는 **자연 삼차 스플라인**으로 교체했다. "자연(natural)" 경계 조건은 양 끝
포인트에서 2차 도함수(곡률)를 정확히 0으로 고정하는 것 — 즉 양 끝 포인트에는 바깥쪽으로
곡선을 잡아당기는 가상의 콘트롤 포인트가 존재하지 않고, 끝에서 자연스럽게 직선에 가깝게
마무리된다.

### 버그 수정
- 이동(M)/복사(C) 단축키로 노출되는 대상 폴더 트리에서 마우스 클릭 시 하위 폴더가
  확장/축소되지 않던 문제 수정 (다른 트리들과 동일하게 클릭 한 번으로 토글되도록).

### 소스 모듈화
단일 파일(`FolderKit_v07.py`, 약 3,200줄)이 계속 커지고 있어, 아래와 같이 패키지 구조로 재구성했다.

```
FolderKit_v08/
├── FolderKit.py         # 실행 진입점 (얇은 런처)
├── requirements.txt
├── README.txt
├── assets/              # 아이콘 등 정적 자산
│   ├── FolderKit_icon.ico
│   └── FolderKit_icon.svg
├── docs/                # 계획서 및 변경 이력
│   ├── PLAN_v1.md
│   └── CHANGELOG.md     # (이 파일)
└── src/                 # 실제 소스 코드
    ├── paths.py          # 아이콘 등 자산 경로 해석
    ├── styles.py         # 색상 팔레트·상수 (테마 독립)
    ├── config.py         # 환경설정 저장/로드, 최근 작업 히스토리
    ├── sync_core.py      # 동기화 핵심 로직 (스캔/분류/실행, GUI 독립)
    ├── fs_model.py        # 폴더 트리 모델/렌더링
    ├── rename_widgets.py  # 파일명 변경 모드 전용 에디터
    ├── dialogs.py          # 환경설정/미리보기 다이얼로그
    ├── common_widgets.py   # 대기 애니메이션/오버레이
    ├── image_edit.py       # 이미지 편집 모드 핵심(크롭/커브)
    ├── duplicate_finder.py # 중복 파일 찾기 핵심 로직(v09)
    ├── main_window.py      # 메인 윈도우 (모드 통합)
    └── app.py              # 앱 실행(팔레트 적용 + MainWindow 구동)
```

모듈 분리 후 pyflakes로 미정의 이름·누락 임포트를 전수 점검했고, 기존에 확인된 모든 동작
(리네임 폴더 지원, 이미지 편집 적용/저장/배지 지속성, M/C 이동복사, 히스토리 정렬 등)을
헤드리스 환경에서 재검증했다.

### 남은 과제 (다음 단계)
- 커브는 채널별(R/G/B) 개별이 아닌 단일 커브(전 채널 공통)로 구현되어 있음.
- 되돌리기(Ctrl+Z)는 이미지 편집 모드에 아직 없음.
- 계획서의 4번째 모드인 "중복 파일 찾기"는 아직 구현되지 않음.

## v09 — 리네임 아이콘 위치 수정, 되돌리기/재실행, 4번째 모드(중복 파일 찾기)

> ⚠️ 크롭 자체의 남은 문제(사용자 피드백 기준)는 이번 버전에서 아직 손대지 않았다 — 다음 단계로 이월.

### 파일명 변경 모드 — 아이콘을 편집 영역 밖으로 이동
파일/폴더 구분 아이콘(📄/📁)이 편집 텍스트 안에 들어있어 편집 대상처럼 보이던 문제를 수정.
아이콘은 더 이상 텍스트에 포함되지 않고, 에디터 좌측 줄번호 영역(gutter)에 그려진다
(`CodeEditor.line_is_dir` 리스트 기반). 편집 텍스트는 이제 순수 이름만 담는다.

### 이미지 편집 모드 — 되돌리기/재실행 + 단축키
`ImageState`에 이미지별 독립 스냅샷 스택(undo_stack/redo_stack)을 추가해, 크롭 조정·커브
조정·적용(Apply) 시점마다 이전 상태를 저장한다. 새 버튼 두 개(되돌리기/재실행)를 추가하고,
아래 단축키를 배정했다(요청하신 확정 매핑 — 일반적인 Ctrl+Z=되돌리기/Ctrl+Y=재실행과는
반대로 지정되어 있으니 참고):

| 동작 | 단축키 |
|---|---|
| 적용 | Space |
| 저장 | Ctrl+S |
| 되돌리기 | Ctrl+Y |
| 재실행 | Ctrl+Z |

### 신규: 중복 파일 찾기 모드 (계획서 5단계)
`src/duplicate_finder.py` 모듈로 구현. 파일명이 아닌 실제 내용 동일성을 기준으로 판별한다.
- 알고리즘: 크기로 1차 그룹화 → 앞부분 64KB 해시로 2차 그룹화 → 전체 해시로 최종 확정
- 백그라운드 스레드(`DuplicateScanThread`)로 스캔, 진행률 표시 + 중간 취소 지원
- 결과는 그룹별 트리로 표시(그룹 헤더 + 파일별 체크박스), 체크된 파일을 휴지통 삭제 또는
  다른 폴더로 이동 가능
- **1차 범위의 제한사항**: 검사 대상 폴더는 1개(+ 그 하위 폴더 전체)만 지원한다. 계획서
  원안의 "여러 폴더 동시 선택"은 좌측 트리를 다중 선택 가능하도록 확장해야 하는데, 다른
  모드(동기화/리네임/이미지 편집)의 단일 선택 동작에 영향이 가지 않도록 격리하는 작업이
  필요해 다음 단계로 남겨둔다.

### 남은 과제 (다음 단계)
- 크롭 기능 자체의 남은 문제(사용자 피드백) — 다음 세션에서 원인 파악 예정.
- 커브는 여전히 단일 커브(전 채널 공통).
- 중복 파일 찾기의 다중 폴더 선택.

## v21 — send2trash 미탑재 시 완전 차단 대신 영구 삭제 대체, "탐색기 열기" 추가

### "휴지통 삭제 기능을 사용하려면 send2trash 패키지가 필요합니다" 오류 규명
이 메시지는 프로그램이 시작될 때 `send2trash` 모듈을 아예 찾지 못했을 때만
뜬다(`main_window.py` 상단의 `try: from send2trash import send2trash` 가 실패한
경우). 즉 **이 exe를 빌드한 PC의 파이썬 환경에 send2trash가 실제로 설치되지
않은 채로 PyInstaller가 패키징을 한 것**이 원인이다 — `requirements.txt`에는
포함되어 있지만, 이번 빌드 전에 그 환경에서 `pip install -r requirements.txt`
(또는 `pip install send2trash`)를 다시 실행하지 않았을 가능성이 크다.

**재발 방지를 위해 빌드 시 확인할 것**: `pyinstaller` 명령을 실행하는 것과
**같은** 파이썬 인터프리터/가상환경에서 `python -m pip show send2trash`로 설치
여부를 먼저 확인한 뒤 빌드하면 된다.

### 코드 차원의 안전장치 추가
그래도 언젠가 같은 상황이 재발할 수 있으므로, 이제는 send2trash가 없다고 삭제
자체를 막지 않는다. 대신 "휴지통 기능을 사용할 수 없습니다. 휴지통 없이
영구적으로 삭제하시겠습니까?"라고 물어보고, 동의하면 `shutil.rmtree`/`os.remove`로
영구 삭제를 진행한다(좌측 트리 삭제, 중복 찾기의 선택 삭제 모두 동일하게 적용).
당연히 완전 삭제이므로 확인 문구도 명확하게 경고한다.

### 신규 기능 — "탐색기 열기" (Reveal in File Explorer)
좌·우 트리에서 우클릭 메뉴 맨 위에 "탐색기 열기"를 추가했다. VS Code의 같은
기능처럼, 해당 파일/폴더가 들어있는 윈도우 탐색기 창을 열고 그 항목을 바로
선택(하이라이트)된 상태로 보여준다(`explorer /select,"경로"`). macOS(`open -R`),
Linux(`xdg-open`)에서도 각 OS에 맞는 방식으로 동작하도록 만들어 뒀다.

## v20 — 대량 동기화 응답 없음 수정, 새로고침(F5), 삭제 에러 메시지 개선

### 핵심 버그: 파일 20만 개 규모 동기화에서 몇 시간씩 "응답 없음"
원인을 정확히 찾았다 — 동기화 미리보기 창(`PreviewDialog`)이 실행 대상 각 행마다
**실제 `QCheckBox` 위젯**을 만들어 `setCellWidget()`으로 끼워 넣고 있었다. 위젯
인스턴스 생성 비용은 행 수에 비례해 커지는데, 20만 행이면 사실상 끝나지 않는
수준이 된다. 두 가지로 해결했다.
1. 체크박스를 별도 위젯이 아니라 `QTableWidgetItem` 자체의 체크 상태로 처리해
   위젯 인스턴스를 하나도 만들지 않도록 함(수천 건까지는 이 개선만으로 충분히 빠름).
2. 그래도 사람이 수만~수십만 행을 하나하나 스크롤하며 확인하는 건 애초에
   비현실적이므로, 3,000건을 넘는 대량 변경은 행 단위 표 자체를 만들지 않고
   종류별 개수 요약 카드(예: "좌→우 복사 1,203개")만 보여준 뒤 전체 실행/취소로만
   진행하도록 분기했다. 실제로 199,124건을 재현해 다이얼로그 생성 시간을
   측정한 결과 0.1초 이내로 응답하는 것을 확인했다(수정 전에는 사실상 무한정).

### 새로고침(F5) 추가
탐색기 등 외부 프로그램에서 폴더/파일을 추가·삭제해도 화면에 바로 반영되지
않는 문제를 위해 "새로고침(F5)" 버튼을 환경 설정 옆에 추가했다(F5 단축키도
동일하게 동작, 모드와 무관하게 항상 활성화). `QFileSystemModel`의 내부 캐시가
외부 변경을 놓치는 경우를 확실하게 해결하기 위해, 모델을 새로 만들어 트리에
다시 붙이는 방식을 택했다 — 기존 좌·우 선택 경로는 새로고침 후에도 그대로
펼치고 다시 선택된 상태로 복원된다.

### 삭제 실패 메시지 개선 + 다시 시도
폴더/파일 삭제(휴지통 이동)가 실패했을 때, 원인을 알 수 없는 원본 예외 메시지만
보여주던 것을 개선했다. 자주 발생하는 원인(다른 프로그램이 사용 중 — WinError 32,
접근 권한 없음 — WinError 5, 이미 삭제됨 등)을 사람이 이해하기 쉬운 한국어
설명으로 바꿔 보여주고, 원인이 된 프로그램을 닫은 뒤 팝업을 닫지 않고 바로
"다시 시도"할 수 있는 버튼을 추가했다. 중복 파일 찾기의 선택 삭제도 동일한
설명 방식을 적용했다.

## v19 — 환경설정 초기화 버튼 추가

### 배경
v18에서 확인된 것처럼, `Config`/`HistoryManager`는 `QSettings("SRIHS", "FolderSync")`
하나를 공유해서 쓴다. 이 두 문자열이 소스 코드에 고정되어 있는 한, 버전 폴더를
아무리 여러 개로 나눠 관리해도 환경설정과 최근 작업 히스토리는 모든 버전이
동일한 저장소(Windows는 레지스트리, macOS/Linux는 설정 파일)를 함께 쓴다.
이건 의도된 동작(업데이트해도 설정이 유지됨)이지만, 가끔은 완전히 초기화하고
싶을 때가 있다는 요청을 반영했다.

### 환경설정 다이얼로그에 "환경설정 초기화" 버튼 추가
확인 팝업을 한 번 거친 뒤, 저장된 동기화 방향·정책 설정과 최근 작업 히스토리를
전부 초기화한다(`QSettings(...).clear()` — Windows에서는 해당 레지스트리 키
전체 삭제). 초기화 즉시:
- 다이얼로그 안의 라디오 버튼/체크박스가 기본값(양방향/백업 켬/미리보기 켬/
  미러 끔)으로 다시 그려진다.
- 메인 화면의 "최근 작업 히스토리" 콤보박스도 비워진다.

`Config.reset_all()`(정적 메서드)로 구현해 로직을 한 곳에 모았고, 초기화는
OK/Cancel과 무관하게 버튼을 누르는 즉시 반영된다(다이얼로그를 취소해도 초기화
자체는 되돌려지지 않음 — 확인 팝업에 이 점을 명시).

## v18 — 동기화 "차이 없음" 오탐지 원인 규명 및 안내 메시지 개선

### 현상
좌·우가 분명히 다른데도 동기화가 "차이가 없습니다. 이미 동기화 상태입니다."를
반환하는 문제가 보고되었다.

### 원인 (버그 아님 — 설정과 로그 표기의 문제였음)
`decide()`(sync_core.py)는 동기화 방향(`direction`)이 **단방향**일 때 반대쪽에만
있는 항목을 의도적으로 무시하도록 설계되어 있다.

```python
elif direction == "l2r":
    if state in (ONLY_L, NEWER_L): return ("copy", "L2R")
    # 우측에만 있는 것은 원본(좌) 기준이라 무시(미러 시 삭제 후보)
```

환경설정의 동기화 방향이 **좌→우 단방향(l2r)**으로 되어 있는 상태에서, 실제
차이가 전부 "우측에만 있는 파일"(`ONLY_R`)이었다면 `decide()`가 전부 `None`을
반환해 실행할 작업이 0건이 되고, 그 결과 "차이 없음"이 뜨는 것은 **그 방향
설정 기준으로는 정확한 동작**이었다. 실제로 이 경로를 코드로 직접 재현해
확인했다 — 동일한 스캔 결과에 대해 방향을 `both`/`r2l`로 바꾸면 정확히 2건의
동작이 나오지만 `l2r`에서는 0건이 된다.

혼동을 더 키운 부분: 로그에 찍히는 방향 코드값(`l2r`)이 콘솔 글꼴에서 소문자
`l`과 숫자 `1`이 구분하기 어려워 `12r`처럼 보였다(실제 값이 잘못된 게 아니라
표기가 헷갈렸을 뿐).

### 반영한 개선 사항
1. **요청하신 진단 로그**: "동기화" 버튼을 누르는 시점에 좌·우 경로를 로그에
   한 번 더 명시적으로 출력한다("▶ 버튼 클릭 시점 확인"). 좌·우 경로가 완전히
   같으면 그 사실도 즉시 경고로 표시한다.
2. **동기화 방향을 사람이 읽는 문장으로 함께 표시**: 코드값(`l2r` 등) 대신
   "좌→우 단방향(l2r) — 우측에만 있는 파일은 무시(복사 안 함)"처럼 풀어서
   보여줘, 소문자 l/숫자 1 혼동이나 방향 정책 자체를 잊어버리는 것을 방지한다.
3. **"차이 없음" 메시지 세분화**: 스캔 결과에 실제로는 차이가 있었지만 단방향
   설정 때문에 무시된 경우, 예전처럼 그냥 "차이가 없습니다"라고만 하지 않고
   "현재 동기화 방향이 단방향으로 설정되어 있어(l2r), 우측에만 있는 항목 N개는
   정책상 무시되었습니다"처럼 정확한 이유와 개수를 알려준다.
4. **스캔 결과 자체도 로그에 요약**: 비교된 총 항목 수와 상태별(`SAME`/
   `ONLY_L`/`ONLY_R`/`NEWER_L`/`NEWER_R`/`CONFLICT`) 분포를 스캔 직후 로그에
   남겨, 앞으로 비슷한 의문이 들 때 이 로그만으로 원인을 바로 확인할 수 있다.

## v16 — 이동/복사 단축키 회귀 수정, 버튼 추가, 저장 확인 팝업

### M/C 단축키가 동작하지 않던 회귀 버그 수정
v11에서 이미지 편집 레이아웃을 상하로 재구성하면서, M(이동)/C(복사)/Esc 단축키가
이미지 뷰어(`imgedit_viewer_stack`)에만 등록되어 있었다. 문제는 이 뷰어 영역이
`QWidget` 기본 포커스 정책(`NoFocus`)이라 실제로 포커스를 가질 수 없고, 썸네일
목록을 클릭해 이미지를 고르는 가장 흔한 흐름에서는 포커스가 썸네일 목록 쪽에
가 있어 단축키가 먹지 않았다(Space/Ctrl+S 등은 v14에서 같은 이유로 이미 한 번
고쳤는데 M/C/Esc는 그때 함께 옮기지 못했다). 이번에 이미지 편집 영역 전체
(`container`)를 기준으로 다시 등록해 해결했다.

### 하단 버튼 그룹에 이동/복사 버튼 추가
단축키(M/C)와 동일하게 동작하는 "이동"/"복사" 버튼을 정보 바에 추가했다. 툴팁으로
단축키를 표시한다.

### 배지가 붙은 이미지를 이동/복사하면 저장 여부를 먼저 확인
현재 이미지에 적용된(배지가 붙은, 아직 저장 전인) 변경 사항이 있는 상태에서
이동/복사를 시도하면, "저장한 후 이동/복사하시겠습니까?" 확인 팝업이 먼저 뜬다.
"예"를 선택하면 저장까지 마친 뒤 대상 폴더 선택 화면으로 넘어가고, "아니오"를
선택하면 저장하지 않고 디스크에 있는 기존 파일 그대로 이동/복사를 진행한다.

## v15 — 커브 팝오버 단축키, 커브 배지 누락, 저장 후 재편집 손상 버그 수정

### 커브 팝오버의 "적용" 버튼에 Space 단축키/툴팁 누락 수정
메인 화면의 "적용" 버튼과 마찬가지로, 커브 편집 팝오버 안의 "적용" 버튼에도
Space 단축키와 툴팁을 추가했다. 팝오버가 열려 있는 동안 Space를 누르면 팝오버의
적용 버튼을 누른 것과 동일하게 동작한다.

### 커브만 조정했을 때 썸네일 배지가 안 붙던 문제 수정
크롭을 적용했을 때와 달리, 커브만 조정하고 팝오버의 "적용"을 눌렀을 때는
`ImageState.applied`가 갱신되지 않아 썸네일에 배지가 표시되지 않았다. 이제 커브
조정도 크롭과 동일하게 "내용이 바뀐 편집"으로 취급해 배지를 표시하고 저장 대기
상태로 표시한다.

### 핵심 버그: 저장 후 같은 이미지를 다시 편집하면 검게 패딩되며 손상되던 문제
가장 중요한 수정. 원인을 정확히 재현해 확인했다 — 크롭을 적용하고 저장하면
디스크의 파일이 원본보다 작은 크롭 결과로 덮어써지는데, `ImageState`의
`crop_rect`/`curve_points`가 초기화되지 않고 예전(더 큰 원본 기준) 좌표를 그대로
들고 있었다. 이 상태로 같은 이미지를 다시 편집(크롭/커브 조정)하면, 이미 작아진
파일을 다시 열어서 예전의(이제는 이미지 범위를 벗어난) 크롭 좌표로 또 자르려다
보니 PIL이 벗어난 영역을 검은색으로 채워 넣었고, 거기에 커브(특히 대비를 높이는
커브)가 겹쳐지면서 화면에 보이던 것보다 훨씬 과격하고 지저분한(색이 깨지는)
결과가 나타났다. 저장이 성공하면 그 시점부터 저장된 파일을 새로운 "원본"으로
간주해야 하므로, 저장 직후 `crop_rect`를 비우고 `curve_points`를 초기값으로
되돌리며, 더 이상 유효하지 않은 되돌리기/재실행 이력도 함께 비우도록 수정했다.
실제로 저장 → 재편집 시나리오를 재현하는 테스트로 수정 전 손상(검은 픽셀)과
수정 후 정상 동작(원본 색상 유지)을 모두 확인했다.

## v14 — 이미지 편집 하단 영역 간격/높이 재조정

### 트리|뷰어 영역과 썸네일 사이 간격이 너무 넓던 문제 수정
기존에는 상단(트리|뷰어)과 하단(썸네일+정보바)을 QSplitter(Qt.Vertical)로 80:20
비율 배분했는데, 창 크기가 커지면 하단 영역도 비율만큼 함께 늘어나면서 썸네일
목록 위에 불필요한 빈 공간이 생겼다. 하단 영역을 더 이상 비율로 배분하지 않고
**내용물에 필요한 만큼만 고정 높이**로 고정하고, 위·아래 사이 간격도 트리|뷰어
사이 간격(4px)과 동일하게 맞췄다. 창을 늘리면 그 여분은 전부 위쪽 뷰어 영역이
가져가므로 하단에 빈 공간이 생기지 않는다.

### 썸네일 목록에 세로 스크롤바가 생기지 않도록 수정
썸네일 목록의 높이를 그리드 한 줄 높이에 정확히 맞추고, 세로 스크롤바를 아예
끄고(`ScrollBarAlwaysOff`) 가로 스크롤바만 필요할 때 표시되도록(`ScrollBarAsNeeded`)
설정했다. 위에서 줄어든 간격만큼을 썸네일 목록 쪽에 배정해, 한 줄 전체가 잘리지
않고 보이도록 했다.

### 버튼 레이블 폰트 크기 원복 + 패널 높이 축소 방식 변경
"버튼이 위치한 패널의 세로 사이즈를 줄여달라"는 요청을 지난 버전에서 버튼 글자
크기를 줄이는 것으로 잘못 반영해, 다른 버튼들과 글자 크기가 달라 보이는 부작용이
있었다. 글자 크기는 앱 전반과 동일한 12px로 되돌리고, 대신 버튼 자체의 높이만
줄이고(28px → 22px) 레이아웃 여백을 최소화하는 방식으로 패널의 세로 크기를
줄였다.

## v13 — 되돌리기/재실행 단축키 정정, 적용 버튼 툴팁, 선택된 썸네일 파일명 미표시 수정

### 되돌리기/재실행 단축키가 서로 뒤바뀌어 있던 문제 수정
확정 매핑을 **되돌리기=Ctrl+Z, 재실행=Ctrl+Y**로 정정했다(일반적인 관례와 일치).
버튼 툴팁과 실제 QShortcut 등록을 모두 맞춰 고쳤다.

### 적용 버튼에 단축키 툴팁이 없던 문제 수정
"적용" 버튼에 `Space` 툴팁을 추가해, 저장/되돌리기/재실행 버튼과 마찬가지로
마우스를 올리면 단축키가 보이도록 했다.

### 선택된 썸네일의 파일명이 안 보이던 문제 수정
원인은 스타일시트에서 선택 상태(`::item:selected`)의 배경색만 지정하고 글자색은
지정하지 않아서, Qt가 기본으로 적용하는 "선택 강조 글자색"(보통 흰색)이 옅은 배경
위에서 거의 안 보이게 된 것이었다. 선택 상태에도 명시적으로 어두운 글자색을
지정해 해결했다.

## v12 — 이미지 뷰어 테두리, 단축키 범위, 체이닝 크롭, 썸네일 정렬/축소

### 이미지 뷰어 테두리 미적용 버그 수정
`CropCanvas`처럼 커스텀 `paintEvent`를 가진 `QWidget`은 `WA_StyledBackground` 속성이
없으면 스타일시트의 `background-color`/`border`가 실제로 그려지지 않는다. 이 속성을
켜서 v11에서 추가했던 테두리가 실제로 보이도록 수정했다.

### 단축키(Space/Ctrl+S/Ctrl+Y/Ctrl+Z)가 동작하지 않던 문제 수정
v11에서 레이아웃을 상하로 재구성하면서, 이미지 뷰어(크롭 캔버스)가 단축키가 등록된
`bottom_wrap`(썸네일+버튼 영역)과 서로 다른 위젯 트리에 놓이게 되어, 뷰어나 좌측
트리에 포커스가 있을 때 단축키가 먹지 않았다. 단축키를 이미지 편집 영역 전체를
아우르는 `imgedit_vsplit` 기준으로 다시 등록해 해결했다.

### 핵심 버그: 적용된 이미지 위에서 다시 크롭하면 원본으로 되돌아가던 문제
가장 중요한 수정. 지금까지는 크롭을 적용(preview 상태)한 뒤 다시 드래그해서 크롭
영역을 그리려고 하면, 클릭 즉시 "원본 이미지 + 이전 크롭 오버레이"로 강제로
되돌아가 버렸다(v05부터 있던 `클릭하면 다시 편집` 방식의 부작용). "크롭한 이미지를
유지한 채 그 위에서 다시 크롭"을 원한다는 피드백에 따라 이 되돌리기 동작 자체를
제거했다. 이제 preview 상태에서도 곧바로 드래그해서 새 영역을 그릴 수 있고,
그 좌표는 "현재 화면에 보이는(이미 한 번 잘린) 이미지" 기준이므로, 내부적으로
이전 크롭의 오프셋을 더해 원본 파일 기준 절대 좌표로 합성한다(체이닝 크롭).
다른 썸네일로 이동했다 돌아온 뒤에도 동일하게 정상 동작한다.

### 썸네일 정렬 및 축소
- 이미지마다 가로세로 비율이 달라 아이콘 상자 크기가 들쭉날쭉하던 것을, 항상
  정사각형(레터박스 패딩)으로 만들어 모든 파일명이 같은 높이에 정렬되도록 수정.
- 선택 시 테두리가 파일명을 가리던 문제를 grid 크기 확보 + 항목 패딩으로 해결.
- 파일명이 2줄을 넘으면 뒤를 말줄임(…) 처리하고, 전체 이름은 툴팁으로 확인 가능.
- 썸네일 아래 적용/저장/되돌리기/재실행 버튼 영역의 높이를 기존 대비 절반 수준으로
  축소(28px → 20px, 글자 크기도 축소).

## v11 — 분할 비율 좌우 반전 수정, 리네임 아이콘 선명화, 이미지 편집 레이아웃 재구성

### 좌우 분할 비율 방향 수정
v10에서 "이미지 편집·중복 찾기 = 80:20"을 좌:우로 해석해 좌측 트리가 80%(큼), 우측
작업 영역이 20%(작음)이 되어 있었다. 실제 의도는 반대(좌측 트리 20%, 우측 작업영역
80%)였음을 확인하고 두 모드 모두 20:80으로 수정했다.

### 파일명 변경 모드 — 파일/폴더 아이콘 선명화
기존의 얇은 외곽선 아이콘 대신, 폴더는 실제 폴더처럼 노란색으로 채워 표현하고
파일은 흰 문서에 가로줄 3개를 그은 "작성된 문서" 느낌으로 다시 그려 두 아이콘이
한눈에 뚜렷하게 구분되도록 했다.

### 이미지 편집 모드 — 레이아웃 재구성
기존에는 좌측 트리가 세로 전체를 차지하고 우측에 미리보기+썸네일이 있어, 트리가
썸네일 영역을 뚫고 지나가는 것처럼 어색해 보인다는 피드백을 반영했다. 이제 먼저
상하로 나누고(위: 좌측 트리 20% · 우측 이미지 뷰어 80% — 좌우 분할, 아래: 썸네일
스트립 + 정보 바가 전체 폭을 차지), 이미지 뷰어에는 안정감을 위한 테두리를 추가했다.
좌측 트리(tree_source)는 다른 모드와 공유하는 위젯이라, 모드 전환 시마다
`_ensure_tree_source_parent()`가 해당 모드에 맞는 컨테이너로 자동으로 옮겨 붙인다.

### 모드 아이콘 — 동기화 아이콘을 앱 아이콘 모티브로 교체
4개 모드 버튼 중 첫 번째(동기화)가 앱의 핵심 기능이라는 점에서, 기존의 추상적인
화살표 아이콘 대신 FolderKit 앱 아이콘의 모티브(폴더 + 좌우 동기화 화살표)를
가져와 같은 원형 배지 스타일로 재해석해 적용했다.

## v10 — 중복 찾기 다중 폴더 선택, 좌우 분할 비율 통일, 아이콘 일관성

> 크롭 자체의 남은 문제는 이번 버전에도 아직 손대지 않았다(요청에 따라 보류).

### 중복 파일 찾기 — 다중 폴더 선택
계획서 5단계의 남은 제한사항(단일 폴더만 지원)을 해결. 다른 모드의 우클릭 메뉴와는
확실히 구분되도록, 중복 찾기 모드에서 좌측 트리를 우클릭하면 기존 메뉴 대신
**"폴더 추가 (중복 검사 대상)"** 단일 항목만 노출되는 전용 메뉴가 뜬다. 선택할 때마다
누적 목록이 하단 콘솔에 계속 출력되어 지금까지 등록한 폴더를 바로 확인할 수 있다.
"스캔 시작"을 누르면 대상 폴더 전체 목록을 보여주는 확인 팝업이 한 번 뜨고, 확인해야
실제 스캔이 시작된다. 스캔 중에는 진행률 바(%)가 갱신되고, 콘솔에 처리 중인 파일이
계속 출력된다. `DuplicateScanThread`가 여러 루트를 받아 하나의 파일 집합으로 합쳐
탐색하도록 확장했다(폴더끼리 하위 경로가 겹쳐도 같은 파일을 중복 집계하지 않음).

### 좌우 창 크기 통일
모드 전환 시마다 좌우 분할 비율을 아래 기본값으로 리셋한다.
- 동기화 / 파일명 변경: 50:50
- 이미지 편집 / 중복 파일 찾기: 80:20 (우측 작업 영역을 넓게)

구현 중 실제 버그를 하나 발견해 수정했다: `QSplitter.setSizes([50, 50])`처럼 작은
비율 숫자를 그대로 넘기면 Qt가 그 비율을 무시하고 위젯 sizeHint 기반의 엉뚱한 배분
(예: 19:81)을 해버리는 경우가 있었다. 스플리터의 실제 폭을 기준으로 목표 픽셀 값을
직접 계산해서 넘기도록 고쳐 해결했다. (다만 창 폭이 좁으면 우측 패널의 최소 폭
제약 때문에 80:20이 75:25 정도로 완화될 수 있다 — 패널이 지나치게 좁아지는 것을
막기 위한 정상적인 동작이다.)
