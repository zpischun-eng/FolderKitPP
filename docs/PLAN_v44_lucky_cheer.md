## 0. 개요

| 항목 | 행운의 번호 | 응원의 메시지 |
|---|---|---|
| 앱 id (내부 키) | `lucky_draw` | `cheer_arrow` |
| 표시 이름 | 행운의 번호 | 응원의 메시지 |
| 카테고리 | 학급·수업 도구 (좌석표·대진표와 같은 곳) | 학급·수업 도구 |
| 주 용도 | 수업 발표자 뽑기, 행사 경품·번호표 추첨, 사전 등록 명단 추첨 | 조회·종례, 시험 기간, 수능 D-day 응원 |
| 최대 규모 | 120명(번호) | 기본 + 교사 메시지 수백 개 |
| 언어 | UI는 기존 i18n 정책 유지 | 메시지 콘텐츠는 1차에 한국어만 |
| 핵심 기술 | 2D 물리(원형 공 충돌), 7비트 이진 라우터 연출 | 포물선 비행, 풍선 부유, 충돌·파티클 |

두 앱 모두 기존 미니앱에는 없던 **실시간 애니메이션(60fps)** 이 필요하다. 따라서 공용 애니메이션 기반 모듈(`anim_kit`)을 먼저 만들고 두 앱이 함께 사용한다.

### 공통 원칙

- **내부 키와 표시 문구 분리.** 모드, 테마, 상태, 메시지 식별자는 모두 언어와 무관한 내부 키(`drum`, `router`, `base_017` 등)로 저장하고 비교한다. 화면에 보일 때만 i18n 문구로 변환한다. 콤보박스는 `addItem(표시문구, userData=내부키)` 형식으로 만들고, 분기는 `currentData()`로만 판단한다.
- **로직과 렌더링 분리.** 코돈시뮬(`codon.py` / `codon_solve.py`)과 같은 방식으로, 추첨·메시지 선택·충돌 판정은 `*_logic.py`에 두고 헤드리스로 테스트한다.
- **UI 규격(v34) 준수.** `split_lr` 골격을 쓰고, 우측 패널은 340px 고정, 모든 구역은 제목 있는 카드로 만든다. 버튼은 주/보조/위험 3등급을 쓰고, 캔버스는 카드 안에 배치한다.
- **전체화면 발표 모드.** 두 앱 모두 프로젝터 사용이 주 용도다. 우측 패널을 숨기고 캔버스만 전체화면으로 띄우는 모드를 제공한다.

## 1. 공용 애니메이션 기반 `anim_kit`

### 1.1 모듈 구성

```
src/utils/anim_kit/
  __init__.py
  loop.py        # 고정 시간 간격 루프 (QTimer + 누적 시간)
  physics2d.py   # 원-원 / 원-벽 / 선분 충돌, 공간 격자 분할
  particles.py   # 파티클(터짐, 반짝임, 꽃가루) 풀
  sprites.py     # 공·풍선 스프라이트 사전 렌더링 캐시 (DPR 반영)
  canvas.py      # AnimCanvas(QWidget): 루프 연결, 가시성 감지, 전체화면
```

### 1.2 루프 설계

- 물리 스텝은 **고정 1/120초**, 렌더링은 `QTimer(16ms)`로 한다. 경과 시간을 누적해서 필요한 만큼 물리 스텝을 돌리는 방식(fixed timestep + accumulator)이다.
- 한 프레임에 돌릴 물리 스텝 수에 상한(예: 8회)을 둔다. PC가 느려져도 스텝이 계속 밀리며 화면이 멈추는 현상(죽음의 나선)을 막기 위해서다.
- `hideEvent`나 미니앱 전환 시 루프를 정지하고, `showEvent` 때 재개한다. 다른 미니앱을 쓰는 동안 CPU를 쓰지 않게 한다.
- 난수는 루프가 소유한 `random.Random(seed)` 하나만 쓴다. 이 규칙을 지켜야 재현(1.4)이 가능하다.

### 1.3 성능 대책 (120개 공 기준)

- **충돌 검사.** 모든 공 쌍을 검사하면 7,140쌍이고, 1초에 120스텝이면 약 86만 회가 되어 순수 Python으로는 부족하다. 공 지름 크기의 **균일 격자 공간 분할**을 쓰면 공 하나당 인접 칸의 공만 검사하므로 스텝당 수백 쌍 수준으로 줄어든다.
- **렌더링.** 번호가 적힌 공은 번호별로 `QPixmap` 스프라이트를 미리 그려 캐시하고, 매 프레임에는 `drawPixmap`만 호출한다. 캐시는 `devicePixelRatioF()`를 반영해 만든다(v43.x 미리보기 화질 버그와 같은 문제 예방).
- **목표 성능.** 일반 교실 PC에서 120개 공, 60fps를 유지한다. 부족하면 물리를 1/60초 스텝 + 2회 서브스텝으로 낮추는 설정을 둔다.

### 1.4 재현 가능성 (공정성 근거)

- 추첨 회차마다 `secrets.randbits(64)`로 시드를 만들어 기록한다.
- 고정 시간 간격 루프는 같은 시드, 같은 입력 프레임이면 같은 결과를 낸다.
- 결과 기록에는 **시드, PICK 입력 프레임 번호, 결과**를 남긴다. 이의가 생기면 "추첨 재현"으로 같은 장면을 다시 보여 줄 수 있다.
- 부동소수점 특성상 서로 다른 PC 사이의 완전한 동일성은 보장하지 않는다. 계획서와 도움말에는 "같은 PC에서 재현"이라고 명시한다.

### 1.5 `UtilHost` 확장

- `request_fullscreen(widget)` / `exit_fullscreen()`을 추가한다. 화면 캡쳐 앱에서 "메인 창 숨김"을 추가했던 것과 같은 방식이다.
- 전체화면에서는 `Esc`로 복귀하고, 스페이스·엔터를 주 동작(섞기/뽑기, 발사)으로 쓴다. 발표 리모컨의 페이지 넘김 키(PageDown)도 주 동작에 연결한다.

## 2. 행운의 번호 `lucky_draw`

### 2.1 콘셉트: "선린 패킷 추첨기"

흔한 로또 드럼을 그대로 쓰지 않고, **인터넷고등학교다운 네트워크·컴퓨터 구조**를 추첨 과정 자체에 담는다. 번호 공은 **데이터 패킷**이고, 추첨은 **패킷이 코어에서 라우팅되어 목적지(당첨자)에 도착하는 과정**이다.

연출 방식은 두 가지를 제공한다. 내부 키는 `drum`과 `router`다.

| 연출 모드 | 내부 키 | 결과를 결정하는 것 | 어울리는 상황 |
|---|---|---|---|
| 코어 챔버 | `drum` | 물리 시뮬레이션 (흡입구에 먼저 들어간 공) | 행사, 경품 추첨처럼 긴장감이 필요할 때 |
| 이진 라우터 | `router` | 7비트 난수 (한 비트씩 공개) | 수업 발표자 뽑기, 정보 수업과 연계할 때 |

### 2.2 연출 모드 A: 코어 챔버 (`drum`)

**화면 구성**

- 원형 챔버를 **PCB(회로 기판) 스타일**로 그린다. 테두리에 회로 패턴이 흐르고, 바닥에 "쿨링 팬"(공기 분사구) 3개가 있다.
- 공은 패킷 칩 느낌의 원형이다. 공에 번호를 쓰고, 번호대별 색상은 명단 인원에 맞춰 자동 구간(최대 6색)으로 나눈다.
- 챔버 상단에 **흡입 포트**가 있고, 포트에서 **회로 트레이스(배선)** 가 화면 오른쪽 **출력 터미널**까지 이어진다.

**동작 흐름**

1. **대기.** 공들이 챔버 바닥에 쌓여 있다.
2. **[섞기]** 를 누르면 팬이 가동된다. 팬 위 구역의 공에 위쪽 충격량과 난수 섞인 좌우 충격량을 준다. 팬 회전 속도 게이지와 "OVERCLOCK" 표시등이 켜진다.
3. **[뽑기]** 를 누르면 흡입 포트가 열린다. 포트 판정 영역에 **처음 들어간 공이 당첨**된다. 연출이 아니라 물리 결과로 결정된다.
4. 당첨된 공은 물리 세계에서 빠지고, 정해진 궤적 애니메이션으로 회로 트레이스를 따라 빛을 내며 이동한다.
5. **출력 터미널**에 도착하면 결과를 공개한다(2.4).
6. 뽑힌 공은 하단 **"수신 완료" 트레이**에 순서대로 쌓인다.

**구현 메모**

- 흡입은 포트가 열리는 동안 포트 근처 공에 약한 끌림 힘을 주는 방식이다. 3초 안에 아무 공도 들어가지 않으면 팬 출력을 자동으로 올린다.
- 공 반지름은 인원 수에 따라 자동으로 정한다. 챔버 면적 대비 공 면적이 약 35~40%가 되게 한다. 120개일 때도 공이 서로 겹치지 않고 번호가 읽히는 크기가 기준이다(1080p 전체화면에서 지름 약 34px).
- 인원이 적으면(예: 10명) 공이 너무 커지므로 최대 지름에 상한을 둔다.

### 2.3 연출 모드 B: 이진 라우터 (`router`)

선린다운 차별화 포인트다. 120명은 7비트(2⁷ = 128)로 표현할 수 있다는 점을 연출의 중심에 둔다.

**화면 구성**

- 화면 위쪽에 **입력 포트**가 있고, 아래로 7단의 **이진 분기 게이트(라우터)** 가 트리 모양으로 펼쳐진다.
- 맨 아래에 목적지 슬롯이 있다. 1~120번 슬롯이 보이고, 121~128번은 "미할당 주소"로 흐리게 표시된다.
- 화면 옆에 **비트 레지스터** `[ _ _ _ _ _ _ _ ]`가 표시된다.

**동작 흐름**

1. **[전송]** 을 누르면 패킷 공이 입력 포트에서 떨어진다.
2. 각 게이트에서 비트(0=왼쪽, 1=오른쪽)가 결정된다. 공이 그쪽으로 굴러가고, 비트 레지스터가 한 칸씩 채워진다. 예: `1 0 1 1 0 0 1`
3. 7비트가 모두 차면 레지스터가 10진수로 변환된다. 예: `1011001₂ = 89`. 이어서 89번 슬롯에 도착하고 결과를 공개한다.
4. 미할당 주소(121~128)나 이미 뽑힌 번호에 도착하면 **"패킷 폐기 → 재전송"** 연출 후 다시 떨어뜨린다. 거부 표본 추출(rejection sampling)을 네트워크의 재전송으로 표현한 것이다.

**공정성**

- 비트는 물리 충돌이 아니라 **`secrets` 기반 난수 비트**로 정하고, 공의 움직임은 그 결과를 보여 주는 애니메이션이다. 핀볼처럼 물리로 떨어뜨리면 가운데 번호가 많이 나오는 이항분포가 되기 때문이다.
- 재전송을 포함하면 모든 유효 번호의 확률이 정확히 같다(균등분포).
- **후반부 대책.** 남은 번호가 적어지면 재전송이 많아진다(예: 120명 중 110명을 뽑은 뒤에는 성공 확률 10/128). 따라서 남은 인원이 트리 용량의 절반 이하가 되면 **남은 후보만 다시 번호를 매기고 트리 단수를 줄인다.** 예를 들어 10명이 남으면 4단(16슬롯)이 된다. 이렇게 하면 재전송 확률이 항상 50% 미만이다. 단수가 바뀔 때는 "라우팅 테이블 갱신" 연출을 짧게 넣는다.
- 인원이 64명 이하이면 처음부터 6단, 32명 이하이면 5단처럼 자동으로 조정한다.

**수업 연계 효과**

정보 수업에서 이진수, 비트 수와 표현 범위(2ⁿ), 거부 표본 추출의 원리를 설명할 때 그대로 쓸 수 있다. 도움말에 "왜 7단인가요?" 설명 카드를 하나 넣는다.

### 2.4 결과 공개: 터미널 복호화 연출

두 모드에서 공통으로 쓴다.

- 결과 카드는 터미널 창 형태다. 먼저 `> decrypting packet #089 ...` 한 줄이 타이핑된다.
- 이어서 이름 자리에 무작위 한글·기호가 빠르게 바뀌다가, 왼쪽부터 한 글자씩 실제 이름으로 고정된다(스크램블 디코딩).
- 고정이 끝나면 카드가 확대되고 파티클이 터진다. 명단이 없는 번호 모드에서는 번호만 크게 표시한다.
- 연출 속도는 `빠르게 / 보통 / 극적으로` 3단계로 제공한다(내부 키 `fast`, `normal`, `dramatic`). 수업 중 연속 추첨에는 "빠르게"가 필요하다.

### 2.5 추첨 유형

| 추첨 유형 | 내부 키 | 설명 |
|---|---|---|
| 번호 범위 | `range` | 시작~끝 번호(최대 120개). 예: 1~30 |
| 명단 추첨 | `roster` | 기존 명단 로더(좌석표·대진표 공용)로 불러온 명단. 최대 120명 |
| 조합 뽑기 | `combo` | N개 중 K개를 한 번에 뽑아 정렬해 표시. 예: 45개 중 6개 |
| 번호표 발급 | `ticket` | 명단 전원에게 겹치지 않는 번호를 무작위로 부여하고 인쇄 |

- **번호표 발급**은 애니메이션 없이 즉시 섞고, 결과 표를 `print_grid`로 인쇄한다. 행사장 번호표를 미리 부여하는 용도다. 결과는 CSV로도 내보낸다.
- 조합 뽑기의 이름은 "로또" 대신 중립적인 명칭을 쓴다.

### 2.6 옵션

- **당첨자 제외** (기본 켬): 뽑힌 번호는 다음 추첨에서 빠진다. 끄면 복원 추첨이 된다.
- **결석·제외 번호 지정**: 명단 트리에서 체크를 해제해 제외한다.
- **연속 뽑기 수**: 한 번에 1~10명을 연속으로 뽑는다. 경품 추첨에서 "3등 5명"을 한 번에 처리할 때 쓴다.
- **추첨 회차 이름**: 예: "3등 상품", "발표 순서". 결과 기록의 그룹 이름으로 쓴다.
- **테마**: `pcb`(기본, 선린 PCB 스타일), `terminal`(검은 바탕 녹색 모노스페이스), `classic`(일반 행사용 밝은 색). 학교 CI 색상은 설정에서 강조색으로 지정할 수 있게 한다(색상 값은 학교 CI 가이드 확인 후 입력).

- **내부 키**: 모드·유형 분기가 표시 문구가 아닌 내부 키로만 이루어지는지 확인한다(언어를 바꾼 뒤 저장·불러오기 테스트).

## 3. 응원의 메시지 `cheer_arrow`

### 3.1 콘셉트

하늘에 떠 있는 풍선을 활로 맞혀 터뜨리면, 그 안에 숨은 **오늘의 메시지**가 나타난다. 메시지는 **기본 메시지 + 교사 입력 메시지**에서 뽑히고, **날마다 달라지며, 모든 메시지가 한 번씩 나올 때까지 반복되지 않는다.**

### 3.2 게임 흐름

1. 화면 왼쪽 아래에 활을 든 궁수 실루엣이 있고, 오른쪽 하늘에 풍선 5~7개가 흔들리며 떠 있다.
2. 마우스로 활시위를 **뒤로 끌어** 조준한다. 끄는 거리가 힘, 방향이 각도다. 예상 궤적 점선(보조선)을 켜고 끌 수 있다.
3. 놓으면 화살이 포물선을 그리며 날아간다. 화살 머리는 속도 방향으로 회전한다.
4. 풍선에 맞으면 풍선이 터지며 조각과 색종이 파티클이 흩어지고, 메시지 카드가 풍선 자리에서 펼쳐진다.
5. 메시지 카드를 클릭하거나 스페이스를 누르면 닫히고, 다음 풍선을 쏠 수 있다.
6. 빗나간 화살은 화면 밖으로 사라진다. 3번 연속 빗나가면 보조선이 자동으로 켜진다(수업 시간 낭비 방지).

**풍선 종류**

| 풍선 | 내부 키 | 내용 |
|---|---|---|
| 황금 풍선 (1개) | `today` | **오늘의 메시지** (그날의 대표 메시지) |
| 일반 풍선 | `extra` | 추가 응원 메시지 |

**난이도 옵션** (내부 키 `easy`, `normal`, `hard`)

- 쉬움: 보조선 항상 표시, 바람 없음, 풍선이 크다.
- 보통: 보조선 없음, 약한 바람.
- 어려움: 바람 세기가 매번 바뀌고, 풍선이 더 크게 흔들린다.

**학생 참여 방식**: 학생이 교사용 PC나 전자칠판에서 직접 쏘는 것을 상정해, 터치 드래그로도 조준할 수 있게 한다.

### 3.3 메시지 선택 규칙 ("그날그날 다른 메시지")

**메시지 풀(pool).** 기본 메시지 중 사용 켬인 것과 교사 메시지 중 사용 켬인 것을 합친다.

**덱(deck) 방식.** 풀 전체를 무작위로 섞은 "덱"을 만들고, 앞에서부터 차례로 꺼내 쓴다. 덱이 다 떨어지면 다시 섞는다. 다시 섞을 때 직전 덱의 마지막 5개가 새 덱의 앞 5개에 오지 않게 해서, 덱 경계에서 같은 메시지가 연달아 나오는 것을 막는다.

**하루 단위 고정.**
- 그날 처음 실행할 때 덱에서 풍선 수만큼 꺼내 **"오늘의 세트"** 를 확정하고 날짜와 함께 저장한다.
- 같은 날 다시 열면(다른 반 수업 등) **같은 세트**를 보여 준다. 설정의 "반마다 새 메시지" 옵션을 켜면 실행할 때마다 덱에서 새로 꺼낸다(내부 키 `per_day` / `per_run`).
- 다음 날이 되면 새 세트를 꺼낸다. 건너뛴 날(주말·방학)은 덱을 소모하지 않는다.

**날짜 지정 메시지 (교사 기능).**
- 교사 메시지에 표시 날짜를 지정하면, 그날은 덱과 관계없이 그 메시지가 **황금 풍선(오늘의 메시지)** 이 된다. 예: 수능 전날 "지금까지 충분히 잘해 왔다" 같은 담임의 한마디.
- 같은 날짜에 지정 메시지가 여러 개면, 첫 번째는 황금 풍선에, 나머지는 일반 풍선에 우선 배정한다.
- 날짜 지정 메시지도 그날 쓰이면 덱에서 "사용됨"으로 처리해, 가까운 날에 다시 나오지 않게 한다.

**가중치 옵션.** "교사 메시지 우선"(기본 켬)을 켜면 덱을 섞을 때 교사 메시지를 덱 앞쪽 절반에 고르게 분산해, 새로 입력한 메시지가 빨리 등장하게 한다.

### 3.4 메시지 데이터

**기본 메시지 (앱에 포함, 1차 약 120개)**

| 분류 | 내부 키 | 개수(안) | 예시 방향 |
|---|---|---|---|
| 응원 | `cheer` | 40 | 일상 응원, 친구에게 하는 말투 |
| 격언 | `quote` | 40 | 공개된 옛 격언·속담 (출처 표기) |
| 시험 | `exam` | 20 | 시험 기간, 수행평가 |
| 도전 | `maker` | 20 | 코딩·창작·실패와 재도전 (선린 학생 정서) |

- 격언은 **출처가 확실한 것만** 인물명을 표기한다. 인터넷에 떠도는 "~가 말했다" 식 격언은 오귀속이 많으므로, 확인되지 않으면 `속담` 또는 `작자 미상`으로 표기하거나 제외한다.
- 기본 메시지 초안은 개발 단계에서 따로 작성해 교사 검토를 받은 뒤 확정한다.
- 기본 메시지는 앱 안에서 **삭제 대신 사용 끄기**만 가능하다. 앱을 업데이트할 때 기본 메시지 목록이 교체되어도 교사의 사용 설정은 유지된다(식별자 기준 병합).

**교사 메시지**

- 우측 패널의 "메시지 관리" 카드에서 추가·수정·삭제·사용 켜기/끄기를 한다.
- 입력 필드: 본문(최대 120자), 보조 문구(출처·서명, 선택), 분류, 표시 날짜(선택).
- 엑셀·CSV로 한꺼번에 불러오기와 입력 양식 다운로드를 제공한다(좌석표의 "입력 양식 다운로드"와 같은 흐름).

**저장 형식 (`cheer_messages.json`, `cheer_state.json`)**

```json
{
  "schema": 1,
  "user_messages": [
    {
      "id": "user_7f3a2c",
      "text": "오늘도 한 줄씩, 어제보다 조금 더.",
      "sub": "담임 드림",
      "category": "cheer",
      "date": null,
      "enabled": true
    }
  ],
  "base_disabled": ["base_031"]
}
```

```json
{
  "schema": 1,
  "deck": ["base_012", "user_7f3a2c", "..."],
  "deck_pos": 37,
  "today": {"date": "2026-09-23", "set": ["user_7f3a2c", "base_088", "..."]},
  "mode": "per_day"
}
```

- 덱과 오늘의 세트에는 **메시지 id만** 저장하고 본문은 저장하지 않는다. 교사가 문구를 고쳐도 id가 같으면 고친 문구가 그대로 반영된다.
- 메시지를 삭제하거나 끄면 다음 로딩 때 덱에서 자동으로 빠지고, 새 메시지는 덱의 남은 구간 안 무작위 위치에 끼워 넣는다.
- 메시지 본문은 1차에 한국어만 둔다. 나중에 다국어로 확장할 때는 `text` 필드를 `{"ko": ..., "en": ...}` 형태로 바꿀 수 있게 `schema` 번호를 둔다. UI 문구(버튼·라벨)는 지금처럼 i18n 조각으로 관리한다.

### 3.5 메시지 카드 표시

- 풍선이 터진 자리에서 카드가 펼쳐지고 화면 중앙으로 이동하며 커진다.
- 본문은 큰 글씨로, 보조 문구(출처·서명)는 오른쪽 아래 작은 글씨로 쓴다. 긴 문장은 자동으로 줄바꿈하고 글자 크기를 조절해 프로젝터에서도 읽히게 한다.
- 황금 풍선 카드에는 상단에 "오늘의 메시지"와 날짜를 표시한다.
- 카드 오른쪽 위에 복사 버튼을 두어, 학급 단체방에 바로 붙여 넣을 수 있게 한다.

### 3.6 물리·연출 구현 메모

- **화살**: 위치·속도에 중력과 (옵션) 바람 가속도를 더하는 단순 적분을 한다. 발사 속도는 끈 거리에 비례하고 상한이 있다.
- **풍선**: 기준 위치를 중심으로 사인파 두 개를 합쳐 흔들리고(좌우 주기와 상하 주기를 다르게), 줄이 아래로 늘어진다. 충돌 판정은 화살 끝점과 풍선 타원 사이다. 빠른 화살이 한 스텝에 풍선을 통과해 버리지 않도록, 이전 끝점과 현재 끝점을 잇는 선분으로 검사한다.
- **터짐**: 풍선 색 조각 12~20개와 색종이 파티클을 뿌리고, 0.1초 흰 번쩍임 효과를 준다. 소리는 2차로 미룬다(QtMultimedia 배포 용량 문제).
- **풍선 재배치**: 모든 풍선을 터뜨리면 "오늘의 메시지를 모두 확인했어요" 카드를 띄우고, [다시 띄우기]를 누르면 같은 세트를 다시 볼 수 있다.
- 공용 `anim_kit`의 루프, 파티클, 스프라이트 캐시, 전체화면을 그대로 사용한다.

### 3.7 화면 배치 (`split_lr`)


### 3.9 테스트 항목 (헤드리스)

- **반복 없음**: 풀 크기가 N일 때, 연속 N개 메시지 안에 중복이 없는지 확인한다.
- **덱 경계**: 다시 섞은 직후 5개 안에 직전 덱의 마지막 5개가 없는지 확인한다.
- **하루 고정**: 같은 날짜로 두 번 실행하면 같은 세트가, 다음 날짜면 다른 세트가 나오는지 확인한다(날짜는 주입형 시계로 테스트).
- **건너뛴 날**: 5일 공백 뒤 실행해도 덱이 1세트 분량만 소모되는지 확인한다.
- **날짜 지정**: 지정일에는 해당 메시지가 황금 풍선에 배정되는지 확인한다.
- **편집 반영**: 메시지 문구를 수정하면 오늘의 세트에도 수정된 문구가 표시되고, 삭제하면 덱에서 빠지는지 확인한다.
- **기본 메시지 업데이트 병합**: 기본 목록이 바뀌어도 `base_disabled` 설정이 유지되는지 확인한다.
- **충돌 판정**: 빠른 화살이 풍선을 통과하지 않고 선분 검사로 맞는지 확인한다.

## 5. 결정이 필요한 사항

1. **기본 연출 모드**: 행운의 번호를 처음 열었을 때 코어 챔버와 이진 라우터 중 무엇을 기본으로 할지. 계획서에서는 코어 챔버를 기본으로 두었다.
2. **드럼 결과 결정 방식**: 계획서처럼 "물리 결과로 결정 + 시드 기록"으로 갈지, 두 모드 모두 "난수로 결정 + 물리는 연출"로 통일할지. 전자는 실감이 크고, 후자는 공정성 설명이 단순하다.
3. **응원 메시지의 하루 고정 기본값**: 같은 날 모든 반에 같은 메시지(`per_day`)를 기본으로 할지, 반마다 다른 메시지(`per_run`)를 기본으로 할지.
4. **기본 메시지 초안 검토자**: 격언 출처 확인과 문구 톤 검토를 누가 맡을지.
5. **학교 CI 강조색**: PCB 테마에 적용할 공식 색상 값.
