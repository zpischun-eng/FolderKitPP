## v50 (2026-09-12)

### 🎨 버튼 활성/비활성 스타일 통일 규칙 도입

`setEnabled(False)`로 비활성화해도 겉모습이 그대로인 버튼들이 있었다.
원인은 버튼마다 `background-color`/`color`를 직접 지정하는 커스텀
스타일시트를 쓰고 있어서, Qt가 원래 자동으로 넣어주는 "흐려지는" 효과가
가려졌기 때문. 반대로 "전체 폴더 해제"/"취소"처럼 원래 무채색 계열을
쓰는 버튼은 활성 상태인데도 마치 꺼져 있는 것처럼 보였다.

- **비활성 — 모든 버튼 공통, 예외 없음**: 배경 `#dfe3e8`(연한 무채색) +
  글자 `#a3a9b3`(흐린 회색) + 굵기 보통. 카테고리·색과 무관하게 항상
  이 톤 하나로 통일했다.
- **활성 — 기능별 카테고리로 색 구분**
  - 모드 주 실행(동기화 실행/일괄 적용/커브 적용·저장/빠른 스캔) →
    각 모드 강조색을 그대로 유지
  - 모드 보조 실행(구조 복사/되돌리기·재실행/정밀 스캔) → 기존 색 유지,
    **이동·복사(이미지 편집)는 남색·틸에서 슬레이트(`#607d8b`)로 통일**
  - 파괴적 동작(선택 삭제) → 빨강 `#d32f2f` 유지
  - 중립/유틸리티(취소·전체 폴더 해제·환경설정) → 진한 슬레이트
    `#546e7a`로 통일(비활성의 연한 무채색과 뚜렷이 구분됨)
- 이 규칙은 `styles.py`의 `button_style()` 공용 함수 하나로 구현했다 —
  모든 버튼이 이 함수를 거치므로 앞으로 새 버튼을 추가해도 자동으로
  같은 규칙이 적용된다.

### 🐛 크롭 영역의 우상단(또는 좌상단) 꼭짓점을 드래그하면 반대쪽 꼭짓점이 같이 움직이던 문제 수정

크롭 비율이 자유("free")가 아니라 고정 비율(원본 비율/1:1/4:3/16:9)일 때,
우상단 꼭짓점을 드래그하면 그와 대각선으로 마주보는 좌하단 꼭짓점까지
따라 움직이는 문제가 있었다. 좌상단 꼭짓점을 드래그할 때도 같은 이유로
우하단 꼭짓점이 따라 움직인다(다만 그쪽은 가로 방향도 같이 바뀌다 보니
상대적으로 덜 눈에 띄었을 뿐).

**원인**: 고정 비율일 때 새 높이(h)를 반영하는 코드가 어느 꼭짓점을
드래그하는지와 무관하게 항상 "아래쪽 변(y1)"을 다시 계산하고 있었다.
아래쪽 꼭짓점(좌하단/우하단)을 드래그할 때는 위쪽 변(y0)이 고정 기준점이
맞으므로 문제가 없었지만, 위쪽 꼭짓점(좌상단/우상단)을 드래그할 때는
반대로 아래쪽 변(y1)이 고정 기준점이어야 하는데도 여전히 y1을 다시
계산해 버려서, 건드리지 않은 반대쪽 꼭짓점이 세로로 움직인 것처럼
보였다.

**수정**: 드래그 중인 꼭짓점이 위쪽(좌상단/우상단)인지 아래쪽인지에 따라
고정 기준점을 y1/y0 중 올바른 쪽으로 판별해 다시 계산하도록 고쳤다.
자유 비율(대각선 꼭짓점 제약이 없는 모드)에는 원래부터 영향이 없었다.

## v49 (2026-09-12)

### 🔍 중복 찾기 — "정밀 스캔"을 빠른 스캔 결과의 재검사 전용으로 개편

지금까지는 빠른 스캔과 정밀 스캔이 서로 독립적인 버튼이라, 둘 중 아무거나
먼저 눌러도 매번 대상 폴더 전체를 처음부터 다시 훑었다. 이제는 다음과
같은 2단계 흐름으로 바뀌었다.

1. 처음에는 **빠른 스캔**만 누를 수 있다("정밀 스캔" 버튼은 비활성 상태).
2. 빠른 스캔이 후보 그룹을 찾아 목록에 표시하면 그때부터 **정밀 스캔**
   버튼이 활성화된다.
3. 정밀 스캔을 누르면 폴더를 다시 훑지 않고, **지금 목록에 있는 후보
   파일들만** 전체 내용을 처음부터 끝까지 읽어 재확인한다. 실제로 내용이
   같은 파일만 남고, 아니었던 파일(예: 크기·앞·뒤는 같지만 중간 내용이
   다른 경우)은 자동으로 목록에서 빠진다.
4. 재검사가 끝나면 정밀 스캔 버튼은 다시 비활성화된다(막 검증을 마쳤으므로
   다시 검증할 필요가 없음) — 새로 빠른 스캔을 돌리면 다시 활성화된다.
   재검사 도중 취소하면 원래(빠른 스캔) 결과가 그대로 유지되고, 정밀
   스캔 버튼도 다시 눌러볼 수 있는 상태로 돌아온다.

내부적으로는 스캔 스레드에 "폴더를 훑는 대신 이미 알고 있는 후보
그룹만 전체 해시로 재확인"하는 전용 경로를 추가했고, 캐시·장치별 동시
읽기 제한·진행률 표시·Esc 일시정지/중단은 기존 스캔과 동일하게 그대로
적용된다.

### 🐛 크롭 조정 후 커브를 만지거나, 그 반대로 하면 커브가 초기화되던 문제 수정

크롭 영역을 지정한 뒤 커브를 조정하고 이어서 크롭 영역을 마우스로
움직이면(또는 그 반대 순서로) 방금 만진 커브 조정 내용이 사라지는
문제가 있었다.

**원인**: 커브 팝오버는 `Qt.Popup` 방식 창이라, "적용" 버튼을 누르지
않고 팝오버 바깥(=크롭 캔버스)을 클릭하거나 Esc를 누르면 Qt가 자동으로
팝오버를 닫는다. 그런데 예전 코드는 "적용 버튼을 눌러야만 커브가
확정되고, 그 외의 방식으로 닫히면 조정 내용을 버리고 원래 값으로
되돌린다"고 되어 있었다. 그래서 커브를 만지다가 크롭 영역을
클릭/드래그하려고 한 첫 클릭이 "팝오버를 닫는" 동작으로 처리되면서,
방금 만진 커브가 그대로 버려졌던 것이다.

**수정**: 팝오버가 닫히는 경로(적용 버튼/Space/바깥 클릭/Esc)와
무관하게, 처음 열었을 때와 값이 실제로 달라졌으면 그 값을 그대로
확정하도록 통일했다. 열기만 하고 아무것도 바꾸지 않은 채 닫은
경우에는 예전처럼 아무 일도 일어나지 않는다(괜히 "적용됨" 표시가
붙지 않음). "초기화" 버튼으로 되돌린 뒤 닫으면 그 되돌린 값(커브 없음)이
정상적으로 확정된다.

**참고**: 커브를 만지고 있는 상태에서 크롭 영역을 클릭하면, 그 첫 번째
클릭은 (다른 팝업/드롭다운 메뉴들과 마찬가지로) 팝오버를 닫으면서
커브를 확정하는 데 쓰이고, 크롭 영역 자체를 드래그하려면 이어서 한 번
더 클릭·드래그하면 된다.

### 💬 즐겨찾기 — 메신저 폴더 기본 경로 지정(CoolMessenger)

메신저 폴더는 프로그램마다 저장 위치가 제각각이라 그동안 빈 경로로
두고 환경설정에서 직접 채우도록 안내했는데, 이 학교에서 실제로 쓰는
메신저(CoolMessenger)의 수신 파일 경로를 기본값으로 지정했다.

```
C:\Users\User\Documents\CoolMessenger Files\Received Files
```

- 처음 설치하는 경우 이 경로가 바로 채워진 상태로 시작한다.
- v45~v48에서 이미 즐겨찾기를 써 온 사용자도, 메신저 폴더 경로가 아직
  **비어 있는 경우에만** 이 기본값이 자동으로 채워진다 — 이미 환경설정에서
  직접 다른 경로를 입력해 둔 경우는 그 값을 그대로 유지하고 덮어쓰지
  않는다.
- 경로 중간의 공백("CoolMessenger Files", "Received Files")은 폴더
  이동·클릭 처리 전체가 문자열 통째로 다뤄서(셸 명령으로 쪼개 넘기는
  부분이 없음) 정상적으로 인식된다.

## v48 (2026-09-11)

### 🙈 탐색기가 숨기는 숨김/시스템 폴더($RECYCLE.BIN 등)를 FolderKit에서도 숨김

윈도우 탐색기는 기본 설정에서 "숨김"·"시스템" 속성이 붙은 항목(예:
`$RECYCLE.BIN`, `System Volume Information`)을 화면에 보여주지 않는다.
그런데 FolderKit의 여러 화면은 파일 이름 패턴(`~$*`, `*.tmp` 등)만
검사하고 이 속성 자체는 확인하지 않아서, 탐색기에는 안 보이는 이런
OS 보호 폴더가 그대로 나타나거나 작업 대상에 끼어드는 문제가 있었다.

**영향받던 화면/기능** (전부 탐색기와 동일하게 숨기도록 수정):
- 파일명 변경 모드의 파일/폴더 목록(가장 먼저 발견된 지점)
- 동기화 모드의 스캔·구조 복사·구조 보기(구조 텍스트)
- 중복 파일 찾기 모드의 폴더 스캔
- 이미지 편집 모드의 이미지 파일 목록
- 폴더 트리의 확장 화살표(하위 폴더가 숨김/시스템 폴더뿐이면 화살표도 숨김)

`os.stat().st_file_attributes`(윈도우 전용)로 숨김(0x2)·시스템(0x4)
속성을 직접 확인하는 공용 함수(`is_hidden_or_system`)를 추가해 적용했다.
윈도우가 아닌 환경(맥/리눅스)에서는 이 속성이 없으므로, 이름이 점(.)으로
시작하는 항목만 숨김으로 취급하는 기존 관례로 대체 동작한다.

## v47 (2026-09-10)

### ⭐ 즐겨찾기 바로가기 — 가상 경로 폴더 4종 추가 + 콤보박스로 개편

윈도우 탐색기의 "바탕화면/다운로드/문서/사진/음악/동영상"에 맞춰, 그동안
빠져 있던 **문서·사진·음악·동영상** 4종을 추가했다. 전부 Windows
레지스트리(User Shell Folders)에서 실제 경로를 찾아 자동으로 채운다.
v45~v46에서 이미 즐겨찾기를 저장해 둔 사용자도 다음 실행 시 이 4종만
1회 자동으로 보충되고(기존에 편집해 둔 항목·순서는 그대로 유지), 처음
설치하는 경우는 7종(6개 가상 경로 폴더 + 메신저 폴더)이 한 번에 시딩된다.

- **탐색기풍 아이콘** — 모니터(바탕화면)/아래 화살표(다운로드)/문서 줄
  (문서)/해와 산(사진)/음표(음악)/재생 삼각형(동영상) 모양의 작은 아이콘을
  코드로 그려 붙였다. 완전히 같지는 않아도 탐색기에서 보던 느낌과 비슷하게
  알아볼 수 있도록 했다.
- **그 외 항목은 FolderKit 앱 아이콘** — 메신저 폴더나 사용자가 직접
  추가한 항목에는 이 6종 전용 아이콘 대신 FolderKit 앱 아이콘을 붙인다.
- **목록 → 콤보박스로 개편** — 항목이 7개로 늘면서 기존 3줄짜리 목록이
  화면을 너무 많이 차지한다는 의견을 반영해, 동기화 모드 우상단의
  "최근 작업 히스토리"와 똑같은 형태(콤보박스)로 바꿨다. 항목을 고르면
  즉시 이동한 뒤 다시 자리표시자로 돌아가고, **가장 최근에 고른 항목이
  목록 맨 위로 올라온다**(좌·우가 같은 목록을 공유하므로 양쪽에 동일하게
  반영됨).
- 환경설정의 즐겨찾기 표에서 이름·경로를 수정해도 아이콘 종류가 유지되도록
  수정(예전에는 설정 창을 열고 닫을 때마다 탐색기풍 아이콘 정보가 사라지는
  문제가 있었음).

### 🎨 앱 아이콘 배경 투명화

FolderKit 앱 아이콘(타이틀바/작업표시줄에 쓰이는 .ico)의 흰색 사각
배경을 제거해 완전히 투명하게 만들었다. 폴더 도형과 동기화 화살표,
주황 배지만 남아 어떤 배경 위에서도 더 깔끔하게 보인다.

### 🗑️ 이미지 편집 모드 — Del 키로 삭제

별도 버튼 없이 **Del** 키만으로 현재 보고 있는 사진을 삭제할 수 있게
했다. 확인 팝업에서 기본 선택 버튼을 "예"로 두어, 마우스 없이
Del → Enter만 반복해도 여러 장을 빠르게 정리할 수 있다. 실제 삭제는
가능하면 휴지통으로 보내고(복구 가능), 휴지통 기능이 없는 환경에서는
영구 삭제 여부를 한 번 더 확인한다. 삭제 후에는 목록·썸네일에서 즉시
제거되고 다음 사진으로 자동 이동한다.

### 🖱️ 중복 파일 찾기 모드 — 폴더 우클릭 메뉴 보강

이전에는 중복 찾기 모드에서 좌측 폴더 트리를 우클릭하면 "검사 대상에
추가" 항목만 단독으로 나오고, 다른 모드에 있는 표준 메뉴(탐색기에서
보기/하위 폴더 만들기/이름 변경/삭제/이 폴더 이름 일괄 변경으로 이동)는
전혀 보이지 않았다. 이제는 "검사 대상에 추가"를 맨 위에 추가로 얹어,
동기화 모드 등 다른 모드와 동일한 메뉴 구성을 그대로 함께 쓸 수 있다.

### 🐛 이미지 편집 모드를 갔다 오면 화면이 깨지는 문제 수정

v45에서 추가한 즐겨찾기 바로가기 기능 때문에 생긴 회귀 버그. 이미지
편집 모드로 갔다가 다른 모드로 돌아오면, 우측 영역에 즐겨찾기 목록만

**원인**: 좌측 트리(`tree_source`)는 모든 모드가 공유하는 위젯인데,
이미지 편집 모드만 레이아웃 구조가 달라서(상하 분할) 모드를 전환할

**수정**: 옮겨 붙이는 대상을 트리 자체가 아니라 "트리+즐겨찾기 목록을
함께 담은 컨테이너 전체"로 바꿨다. 이제 어느 모드로 가더라도 트리와
그 위의 즐겨찾기 목록이 항상 하나로 붙어서 함께 이동한다.

**검증**: 실제 버그가 재현되는 것을 먼저 확인한 뒤(이미지 편집 모드
1회 왕복만으로 스플리터에 위젯이 2개에서 3개로 늘어나며 깨지는 것을
코드로 직접 확인), 수정 후 동기화·리네임·이미지편집·중복찾기 모드를
10회 이상 무작위로 오가도 매번 정상 구조를 유지하는지, 그리고 그
과정에서 즐겨찾기 바로가기 클릭이 계속 정상 동작하는지까지 확인했다.

### 🖼️ 이미지 편집 모드에 "JPG로 변환" 일괄 변환 버튼 추가

HEIC(아이폰 기본 포맷)를 비롯해 PNG·WEBP 등 JPG가 아닌 이미지를 한 번에
JPG로 만들어 주는 버튼을 추가했다. 사용자와 상의해 다음과 같이

  일괄 변환(개별 선택 방식이 아님).
- **원본 처리**: 원본 파일은 전혀 건드리지 않고, 같은 폴더에 같은
  이름의 `.jpg` 파일을 새로 만든다(안전 우선 — 되돌릴 수 없는 삭제나
  덮어쓰기가 없음).

세부 처리:
- **투명 배경**(PNG의 RGBA, 팔레트 투명 등)은 그냥 알파를 버리면 이상한
  색이 섞여 보이므로, **흰 배경 위에 합성**한 뒤 JPG로 저장한다.
- 변환하려는 `.jpg` 이름이 **이미 존재하는 다른 파일과 겹치면** 그
  파일은 절대 덮어쓰지 않고 건너뛴다(결과 팝업에 "n개는 이미 있어
  건너뜀"으로 안내).
- 변환이 끝나면 폴더를 다시 불러와 새로 생긴 `.jpg`가 썸네일 목록에도
  바로 보이도록 했다.
- 실제로 HEIC·투명 PNG·이름이 겹치는 파일·이미 JPG인 파일이 섞인
  폴더로 앱의 실제 코드 경로를 통해 전체 과정을 검증했다: 변환 대상만
  정확히 골라 변환되고, 충돌 파일과 원본은 그대로 유지되며, 투명
  영역이 검게 깨지지 않고 흰 배경으로 자연스럽게 처리됨을 확인.
- 버튼/툴팁/확인 팝업/결과 팝업/로그 메시지 전부 3개 언어(한국어/
  영어/일본어)로 확인 완료.

## v39 (2026-09-06)

### 🔍 폴더 동기화 알고리즘 분석 — 폴더 mtime 스킵은 적용하지 않음

"상위 폴더의 갱신 날짜만 보고 하위 전체를 건너뛸 수 있는가"를 검토했다.
실험으로 확인한 결과, 두 가지 이유로 **안전하지 않아 적용하지 않았다**:

1. 파일 **내용만** 수정하면(이름 변경 없이) 그 파일이 든 폴더의 mtime은
   전혀 바뀌지 않는다.
2. 폴더 mtime 변경은 **위로 전파되지 않는다** — `A/B/C`에 파일을 추가해도
   `C`의 mtime만 바뀌고 `B`, `A`는 그대로다.

동기화 도구에서 이 방식은 변경 사항을 조용히 놓칠 위험이 있어 채택하지
않았다. 대신 안전하게 검증된 개선만 반영했다(`docs/sync_analysis_v39.md` 참고):

- **`scan()`을 `os.scandir()` 기반으로 교체** — 기존 `os.walk()` + 파일마다
  별도 `os.stat()` 대신, scandir가 이미 캐시해 둔 stat 정보를 그대로 사용.
  심볼릭 링크 동작(파일은 따라가고, 디렉터리는 나열만 하고 내려가지 않음)은
  기존과 완전히 동일하게 유지했다(실측 검증 완료).
- **좌/우 스캔을 순차가 아니라 동시에 실행** — 두 폴더가 서로 다른 물리
  드라이브에 있을 때 시간이 단축된다.

### 🌐 다국어(i18n) 적용 범위 완성 — 팝업·콘솔·상태바까지 전부

기존 1차 적용은 버튼·라벨·롤오버 힌트·설정 다이얼로그까지만 다루고
"팝업 창과 콘솔 로그는 범위 밖"이라고 명시되어 있었다. 이번에 그 나머지를
전부 찾아 반영했다.

- **QMessageBox 팝업, 콘솔 로그(logmsg), 상태바(showMessage), 폴더 생성
  입력창(QInputDialog)** 등 총 175곳의 하드코딩된 한국어 문구를 전부
  `tr()` 키로 교체하고 영어·일본어 번역을 채웠다.
- 로그 문구 안에 섞여 있던 "좌/우", "이동/복사", "정밀/빠른", "휴지통/영구"
  같은 세부 단어도 함께 번역되도록 처리했다(그렇지 않으면 문장 틀만
  번역되고 단어가 한국어로 남는 문제가 있었다).
- 동기화 실행 스레드(`SyncThread`)가 콘솔에 남기는 "복사/삭제/실패" 진행
  메시지도 번역 대상에 포함했다 — background 스레드라 기존에는 통째로
  빠져 있었다.
- 언어를 바꾸면 이제 메인 화면뿐 아니라 팝업·콘솔·상태바까지 전부 같은
  언어로 표시된다(3개 언어 × 전체 키 렌더링 검증 완료).

## v38 (2026-09-02)

### 🚀 중복 파일 찾기 — 대용량(TB급) 컬렉션 속도 개선

TB급 동영상 컬렉션에서 중복 파일 찾기가 매우 느리던 문제를 해결했다.
자세한 배경과 실측치는 `docs/dupfind_v38_analysis.md` 참고.

- **"정밀 스캔" / "빠른 스캔" 버튼 분리**
  - 정밀 스캔: 기존과 동일하게 후보 파일 전체를 끝까지 읽어 해시 비교(가장 정확, v37과 결과 100% 동일)
  - 빠른 스캔(신규): 앞/뒤 64KB + 파일 전체에 흩뿌린 16×1MB 샘플만으로 확정. 4GB
    동영상 기준 읽는 양이 약 250배 줄어든다. 실측 기준 전체 읽기량 37배 감소.
  - 빠른 스캔은 휴리스틱이므로, 삭제 전 최종 확인용 `verify_group()` 헬퍼를 추가했다.
- **SQLite 해시 캐시** — `(경로, 크기, mtime)`가 그대로면 재스캔 시 디스크를 읽지 않는다.
- **장치(드라이브)별 동시 읽기 수 제한** — HDD/SSD/NAS를 구분해 과도한 병렬 읽기로
  인한 탐색(seek) 병목을 피한다.
- **xxhash(xxh3_128) 사용** — 미설치 시 SHA-1로 자동 대체. MD5 대비 최대 11배 빠른 해싱.
- **진행률을 파일 개수가 아닌 바이트 단위로 계산** — 4GB 파일과 4KB 파일을 동일하게
  세지 않아 진행률 바가 실제 남은 작업량을 반영한다.
- **🐛 2GB 오버플로 버그 수정** — 진행률 시그널의 `int`가 Qt에서 32비트 C int로
  매핑되어 2GB가 넘는 값에서 `OverflowError`가 나던 문제. `qlonglong`으로 수정.

### ⌨️ 중복 파일 찾기 — 스캔 중 Esc로 중단

- 스캔 진행 중 **Esc**를 누르면 스캔이 잠시 멈추고, 중단 여부를 묻는 팝업이 뜬다.
  - **OK** → 스캔 중단
  - **No** → 멈췄던 지점부터 이어서 진행
- 스캔이 실행 중일 때만 단축키가 활성화되어 다른 모드의 Esc 동작과 겹치지 않는다.

- 최소 500장 / 최대 20,000장(≈400MB)으로 상한을 두어 저사양 PC에서
  시스템이 멈추거나 죽는 상황을 원천 차단
- 10,000장 초과 선택 시 "저사양 PC에서는 느려질 수 있다"는 안내 문구
  한 번 더 표시(값 자체는 이미 안전 범위 내 — 참고용 안내)
- QSettings에 영구 저장, 프로그램 재시작 후에도 유지
- 설정 변경시 실행 중인 캐시에도 즉시 반영(재시작 불필요)
- "환경설정 초기화" 버튼으로 언제든 기본값(3000) 복원 가능
- 레지스트리를 직접 조작하는 등 범위를 벗어난 값이 들어와도 자동 클램프

**내부 구현 개선 — LRU 캐시 자료구조 교체 (list → OrderedDict):**
사용자가 캐시를 크게(10,000~20,000) 설정할 가능성이 생기면서, 기존
Python list 기반 LRU 관리(list.remove()가 O(n))가 캐시가 커질수록
느려지는 문제를 사전에 점검·개선했습니다.
- 실측: list 기반은 20,000개 캐시에서 2,000회 접근에 180ms 소요
- `collections.OrderedDict` 기반으로 교체 → 캐시 크기와 무관하게 항상
  O(1) 성능 확보, 동일 조건 1.1ms (약 160배 향상)
- 이 개선 덕분에 캐시를 얼마나 크게 설정하든 성능 저하 걱정 없음

**검증 (실제 PySide6 환경, 헤드리스 자동화 테스트):**
- 환경설정 UI: 프리셋↔스핀박스 연동, 범위 초과 입력 자동 클램프,
  한/영/일 3개 언어 문구 정상 출력 — 모두 통과
- 종단간: 설정 저장 → 재시작(새 Config 인스턴스) → 값 유지, 실행 중
  캐시 리사이즈(축소/확장) 즉시 반영 — 모두 통과
- 초기화 버튼 클릭시 캐시 설정도 함께 기본값 복원 — 통과
- 비정상 값(레지스트리 직접 조작 등) 자동 클램프 — 통과
- 실사용 시나리오(300장 x 3폴더 순회 재방문 0.05~0.06초,
  1000장 x 4폴더로 캐시 한도 초과시에도 크래시 없이 정상 동작) — 통과

**[추가 발견 및 수정] 프리셋-스핀박스 표시 불일치 버그:**
프리셋(예: "기본 3,000장")을 클릭한 뒤 스핀박스 값을 직접 다른 숫자로
바꾸면, 실제 저장되는 값은 스핀박스 값이 맞지만(기능상 문제 없음)
화면에는 이전에 클릭했던 프리셋이 계속 체크된 것처럼 보여 사용자가
헷갈릴 수 있는 표시 불일치가 있었습니다.
- 스핀박스 값이 바뀔 때마다 프리셋 라디오 체크 상태를 값과 항상
  일치시키도록 동기화 로직 추가 — 값이 프리셋과 같아지면 자동 체크,
  다르면 전부 해제(= "직접 입력" 상태임을 시각적으로 명확히 표시)
- 프리셋 클릭 → 스핀박스 반영, 초기화 버튼 동작 등 기존 로직과의
  상호작용도 함께 검증해 회귀 없음 확인

### ⚠️ 주의사항

- 이미지 폴더 변경시 이전 로딩 작업 자동 중단
- QT 객체는 메인 스레드에서만 조작 (시그널/슬롯 사용)

  가능 (기본값: 3,000장 / 범위: 500~20,000장)
